# 群话题与回复策略

## 设计

所有群使用同一种话题参与策略，不提供积极性数值或调节指令。先识别消息属于新话题还是既有话题；同一话题可穿插其他讨论，不因换人或暂时沉默就拆分。

新话题达到维护者设置的最低参与人数后，才结合人设、兴趣和补充价值选择是否接话，默认两人。人数按不同群成员去重，机器人不计入，同一人连发只算一人。门槛支持全局默认和单群覆盖，范围为1～9人和“10+”，单群可恢复跟随默认。“10+”表示关闭主动回复，实际人数达到或超过十人也不会接话，已有话题的非直接呼叫续话也保持沉默。达到门槛后，每批新消息都持续评估是否接话，不要求新增成员，也不限制评估次数；参与人数越多，模型越倾向接话，但没有补充价值时仍可旁听。

机器人已在该话题发言后，只有群友确实回应、追问、质疑或讨论机器人具体说法，才允许再次选择回应。群友继续讨论相同主题不等于回应机器人。直接呼叫与被拍沿用直接互动入口，跳过人数及续话门槛；全体提醒遵循普通话题策略。

话题判断的引用只使用平台消息编号，不向观察模型提供内部归档编号。每条归属与回应依据独立校验；判断无效时仅对该条重判一次，仍无法确认则完整留存为待确认话题并保持旁听，后续合法消息继续处理。重判只参考该消息之前的讨论，不能用后来发送的机器人发言解释旧消息。直接呼叫仍跳过人数及续话门槛。

话题日志记录话题归属依据、起始消息、参与人数、接话或沉默原因及实际发送结果，只记录简短可见依据，不记录内部推理。已识别的消息完整留存，包含机器人发言前和停止回复后的聊天；正文不沿用模型上下文的截取长度，图片和附件保留归档中的文字占位和元数据，不复制媒体文件。

后台仅列出有实际发送成功记录的话题，按聊天气泡展示。没有回复的话题不出现在列表，也不能绕过列表读取详情。日志按机器人账号和群隔离，仅本机查看，不属于长期记忆或私有迁移包。

## 开发

- `plugins/assistant/llm.py` 的 `assess_topics` 用辅助 API 返回逐条归属、标题、判断依据、是否值得回应及所回应的机器人消息编号。请求携带当前群最低参与人数，近期话题附完整的不同参与者编号，提示模型按既有参与者与本批发送者的并集计数，人数越多越倾向接话。未分类归档按每批最多四十条处理，正文每条向模型提供最多四千字；近期话题提供最近十五分钟更新的十二个话题，各附最近十条消息、每条最多四百字。限制仅作用于模型输入。发给观察模型的消息移除归档主键，仅保留平台 `message_id`；话题入口使用同一编号体系的 `start`，模型返回的所有引用都按平台编号校验。
- `plugins/assistant/groupchat.py` 合并普通消息，间隔使用 `WAKE_INTERVAL_SECONDS`，默认八秒，至少等待两秒。按归档主键顺序分类，不只记录合并后的最后一条。首次启用从近期十五分钟归档开始，随后从持久游标继续；不回溯重建启用前的全部历史。
- `plugins/assistant/topics.py` 在 `logs/topics.sqlite3` 保存话题、完整消息快照、决策和处理游标；使用 SQLite WAL。单次 `record` 严格校验后原子提交；群聊入口按归档顺序逐条调用并推进持久游标。起始消息必须属于当前群已存在且不晚于当前消息的话题，或当前消息自身；回应依据必须指向本话题已成功发出的机器人消息，不能引用其他群、用户发言或未来消息。因果关系使用归档顺序，避免平台秒级时间精度造成误判。`TopicError.code` 仅携带固定错误类别。
- `GroupSettings` 每次读取 `group_chat.json` 中的 `default_min_participants`（缺省为2）及群级 `min_participants`（缺省跟随默认）。数值1～9表示人数门槛，10表示“10+”（关闭主动回复），后台始终显示语义标签而非“10人”。关闭规则在普通话题首次接话及续话前执行，生成期间改为10+时通过现有有效性检查停止尚未发送的主动回复；直接呼叫与被拍仍走直接互动。后台默认设置通过 `/api/defaults` 保存；群资源以空值表示继承，保存时删除群覆盖字段。两处都执行整数范围、读取版本及原值备份检查。
- 人数门槛在进入主 DSH 回合前执行；未达门槛保持旁听，达到后每批新消息均重新判断，不以人数阶段限制评估次数。日志与主回合记录本次实际人数和有效门槛。主回合仍可选择静默、普通回复或复读，不会因为门槛放行就强制发送。批次请求成功后，按平台编号匹配每条结果，缺失或重复结果视为该条无效；仅重判无效项一次，携带 `validation_error`，通过 `recent(before=归档主键, at=消息时间)` 重建当时最近十五分钟的上下文，隐藏后来的话题、消息和参与者。重判成功后使用新结果，仍失败则以“待确认话题”完整保存、禁止主动回复并推进游标，后续条目不受影响；不补发旧消息的回答。整批 API 或 JSON 解析失败时保留未处理游标等待新消息重试；直接互动沿用独立兜底记录并允许回应。
- 平台返回有效消息编号后记录机器人消息并累计回复轮数，同轮分包只计一次。失败发送不让话题进入可见列表。话题归属和已回复状态跨重启保留；过期和限流仍由原发送流程控制。
- `admin/console_topics.py` 只读查询日志，`/api/topics` 提供群筛选、标题搜索及每页五十个话题；`/api/topics/messages` 每页二百条完整消息。前端 `admin/app.js` 用文本节点渲染昵称、正文和原因，避免聊天内容注入页面。起始消息单独标记，成功回复的原因默认展开。
- 话题日志始终记录，不受 `MODEL_TRACE_ENABLED` 控制；凭据沿用诊断过滤。保留时长沿用 `MODEL_TRACE_RETENTION_DAYS`，默认七天，按话题最后更新时间整体清理。启动及运行中每小时检查过期话题；持续活跃的话题保留完整内容。
- 群配置只保存参与门槛等操作策略；兴趣与人设使用顶层全局配置。旧群兴趣归并去重后不再按群读取，话题判断与实际回复使用同一份机器人自身兴趣。

## 使用说明

更新代码后重启机器人和后台，刷新后台页面。在“设置”拖动“默认接话参与人数”并保存；在“群管理”选择群，取消“参与人数跟随默认”后拖动“接话所需参与人数”并保存，可为该群设置独立值。重新勾选并保存即可恢复跟随默认。默认两人，范围为1～9人和“10+”；选择“10+”关闭主动回复，直接 @仍可回应。保存后后续消息生效，无需再次重启，也不会自动发言或补发旧回复。

左侧进入“话题日志”，按群筛选或输入话题标题查询。选择话题查看聊天，起始消息有“话题开始”标记；展开“话题判断与回复原因”查看归属、门槛及发送结果。长话题点击“加载后续聊天”，刷新数据可查看新增消息。图片、附件以归档占位呈现，页面不从外部地址加载聊天媒体。

验证依次检查：未达本群人数门槛不接话；达到后可选择接话；沉默后每批新消息都可再评估，同一批成员继续聊天也适用；同一人连发不提高人数；机器人发言后，群友互聊不继续触发；明确追问机器人说法可以回应；直接呼叫不等待人数；10+时即使超过十人或回应机器人说法也不主动回复，直接 @仍有效。后台只显示成功回复过的话题，同时保留前后的旁听消息。

列表为空时，检查机器人是否已重启、辅助 API 是否可用、是否确实成功发送过消息，以及群筛选条件。诊断事件 `topic_assessment_failed` 表示整批请求或单条重判请求失败；`topic_assignment_invalid` 记录无效消息的平台编号、校验类别和尝试次数，`topic_assignment_repaired` 表示重判通过，`topic_assignment_fallback` 表示已独立留存且保持旁听。`topic_decision` 记录程序放行或沉默原因。`unknown_topic`、`topic_after_message` 分别表示未知或晚于当前消息的话题；`unknown_response`、`response_not_bot`、`response_other_topic`、`response_after_message` 分别表示未知、非机器人、跨话题或晚于当前消息的回应依据。分类内容由模型判断，模拟测试验证数据流与程序门槛，真实话题边界和语义仍需群聊观察。

错误恢复验证：模拟旧消息引用无效、后续消息有效，应仅重判旧消息一次并继续回应后续消息；下一次处理不再包含已留存的失败项。重判失败的普通消息即使人数门槛为1也不主动回复，直接 @仍有效。

自动验证：`python -m unittest tests.test_topics tests.test_groupchat tests.test_mentions_all -q`。日志含群聊天原文，仅供本机维护者查看；不要上传日志数据库或其 WAL 文件。
