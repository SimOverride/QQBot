# 人设

## 设计

一份人设同时描述角色身份、性格、兴趣、相处分寸以及措辞、篇幅、节奏和示例。选择人设即完整切换角色与说话方式，不提供独立风格选择。角色不代表真实身体、模型厂商或现实经历，不改变权限、隐私与工具规则；人设同时影响参与意愿和投入程度。合理求助通常愿意接受，过分请求可以拒绝；接受后不能用玩梗代替认真回答，也不能伪造能力限制或执行结果。

被拍后的具体回应、主动拍人的时机、连续被拍时的分寸和静默场景由每份人设直接描述。公共拍一拍提示词只说明通知字段、工具调用、结果状态和限制，不通过“根据人设反应”代替具体角色内容。

内置默认、小鲸鱼、猫娘、技术宅、损友五份人设。当前表达优化以小鲸鱼为基准，其他模板用于参考测试；模板名称“默认”不代表当前实际选中项。昵称不决定人设。群选择只影响本群；没有覆盖的群和私聊跟随全局默认。模板正文不通过 QQ 导出，不允许聊天直接编辑。

维护者可在保存前检查草稿并对比固定虚构场景下的表达。检查仅提供规则提示，试聊有随机性，不替代人工判断，不修改人设、不写真实记忆、不执行外部动作。

## 开发

- 自然表达说明位于 `prompts/catalog.json` 的 `chat.expression`，`prompts.system_prompt.1` 允许人设影响行为选择；`llm.tasks.0` 以接受委托为任务申请前提。主agent按语境自行判断是否需要澄清。`docs/当前完整提示词说明.txt` 汇总代码默认提示词与小鲸鱼正文，实际请求以后台预览为准。
- 模板存放于 `personas/*.txt`，`默认.txt` 为基础默认文件。UTF-8 编码、CRLF 行尾，每份正文 1 至 12000 字。
- 五份内置模板均有“拍一拍互动”章节：默认随意应声，小鲸鱼轻微嘴硬，猫娘轻快回应，损友在熟人间接梗，技术宅简短直接且不打断排错。每份均描述拍回、主动拍人、收住互动及安静略过的具体场景；示例不是固定台词。
- `plugins/assistant/personality.py` 的 `ProfileStore` 每次请求读取模板，通过单一 `persona` 字段注入回复、参与判断和通知改写。
- `group_chat.json` 中 `default_persona` 保存全局选择，群条目的 `persona.name` 保存覆盖；不存在覆盖时继承默认。
- `console_store.py` 与 `admin_server.py` 仅接受 `persona` 类型模板，保留版本检查、备份和删除引用保护；`admin/app.js` 提供单一人设列表与选择框。
- `migration.py` 迁移人设目录；同名内容冲突时重命名来源文件并更新全局及群引用。独立风格文件不属于当前迁移格式，遇到旧包拒绝导入，不静默丢弃。
- 修改正文下次请求生效，启动校验默认模板；选中的模板缺失或无效时报告配置错误，不泄漏正文。

- `profile_lab.py` 提供五个固定场景与措辞、示例、边界、明显矛盾和长段落的启发式检查。`/api/profile-lab` 校验人设资源与版本；试聊分别调用 `Chat.reply` 生成保存版与草稿回复，使用空历史、禁用搜索及工具，不创建档案。结果通过正式分条函数显示，模型调用后再次检查版本。

## 使用说明

后台“提示词管理”新增、编辑或删除人设；“设置”选择默认人设，“群管理”选择该群人设。“默认”表示跟随全局默认。默认文件、全局选中模板和仍被群使用的模板不可删除。

群管理员、群主或机器人所有者在目标群 @机器人使用：

```text
/人设 列表
/人设 切换 猫娘
/人设 默认
```

新增模板不会自动修改群选择。聊天不接受正文编辑，旧的 `/人格` 和 `/风格` 指令不再使用。更新程序后须重启机器人和后台；之后单纯编辑正文无须重启。

验证时检查后台完整请求预览只含一份人设，并分别测试普通招呼、身份问题、明确求助。检查修改正文后的实时读取、其他群不受影响及默认继承。生成有随机性，配置正确不保证每次措辞完全一致。

验证拍一拍时，分别选择不同人设，检查被拍后的语气与收住互动的方式。要修改具体反应，编辑该人设的“拍一拍互动”章节；调用字段和限额见 [拍一拍](POKE.md)，无需把性格要求复制到公共调用说明中。

导入只接受统一人设的数据。旧版双模板部署需先备份，将正在使用的风格正文并入对应人格，去掉群配置的 `style`，更新程序后重新导出；同一人格被不同群搭配不同风格时应先由维护者确定保留哪份表达方式，不能静默任选。

各人设包含表情使用偏好：小鲸鱼侧重接梗与轻微炸毛，损友侧重翻车与收尾，猫娘侧重轻快互动，技术宅在认真排错时克制用图。通用发送、检索和防重复规则见 [群聊与表情处理](CHAT.md)。

后台选中人设后，先编辑正文，再点击“检查人设草稿”。选择普通闲聊、认真求助、接梗、接受纠正或结束话题，点击“对比试聊（调用模型）”查看两列结果；每次执行两次模型生成，消耗 API 额度。草稿未保存时也可试聊，结果不自动应用；仍需手动保存或确认修改建议的差异。试聊报版本冲突时重新加载资源；运行时错误按 [DSH 配置](DSH.md) 排查。

### 小鲸鱼表达验证

检查合理求助是否仍有用、过分要求是否可以自然拒绝、兴趣话题能否适度展开、被纠正后能否改口，以及拒绝时是否虚构能力或故障。多轮观察语境一致性，不以单句是否命中示例为标准。实际选中项通过全局默认与群覆盖核对，编辑小鲸鱼正文不会自动切换其他会话的人设。

自主探索只表达兴趣和行动选择，实际能力、持续授权、预算与停止条件必须由程序提供；当前人设不会开放浏览器或宿主机操作，也不会自行安排唤醒。
