# 群聊自然复读

## 设计

同群两分钟内，至少两位群友连续发送完全相同的纯文字时，机器人可结合人设、气氛及话题参与规则自然跟读。不要求每次跟随；隐私或不适合传播的内容不跟读。

跟读仅原样发送一条文字，不添加引用、解释、标点或表情。只支持纯文字，不跟随图片、引用消息、指令和明确呼叫机器人的消息。同一人多次发送不构成多人复读，其他内容会打断复读链。

按机器人账号和群隔离，同一文字三十分钟内不再跟读，不将自己的消息作为触发依据。遵守固定话题参与门槛、检查间隔和过时回复取消规则，机器人已接话后不能仅凭新的复读链继续插话。

## 开发

`repeat.py` 的 `RepeatState` 在接收去重后的事件时读取原始文字段，保留空格、换行和标点。记录复读链起始时间、不同发送者及最新消息编号；非纯文字和显式触发会清除候选。候选最多四千字符。

`groupchat.py` 将有效原文放入参与判断的 `state.repeat_candidate`。`llm.repeat.0` 要求模型输出 `repeat` 布尔；存在候选时参与判断不提供工具，避免跟读决策阶段另行拍人等副作用。模型未选择跟读时仍按正常参与判断处理。

选择跟读后重新校验候选与冷却，直接走群消息发送回调，不调用普通回复生成、不经过分条或文本润色。发送前登记内容摘要，三十分钟内不重试，包括发送异常。成功发出的原文写入现有消息归档；即使重启，最近三十分钟内机器人已发送的同文也会阻止跟读。失败尝试只存内存，重启后不保留；复读链本身也不跨重启恢复。

跟读结果记录 `repeat_sent` 或 `repeat_failed`，不适用时记录 `repeat_not_available`。日志沿用全局开关。

## 使用说明

更新后重启机器人，无需新增配置。群内两位成员连续发送相同纯文字即可提供候选，由模型决定是否接梗。参与遵循[固定话题策略](TOPICS.md)。

验证应检查：多人同文时可能跟读，跟读内容与原文完全相同；同人重复、夹杂其他内容、图片、引用、指令不触发；同文三十分钟内不再次跟读；新消息出现后不发送过时原文。没有跟读不一定是故障，也可能是参与判断选择沉默或检查间隔尚未到达。
