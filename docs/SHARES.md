# 平台分享

## 设计

机器人可读取 B 站视频、网易云歌曲、专辑和歌单的标题、作者及公开介绍，以及小黑盒公开帖子的文字正文。歌曲没有独立介绍时提供所属专辑。支持普通链接、分享卡片、引用和已展开的合并转发；群内连续补充中的分享也属于同一请求。

模型按问题需要读取分享，不因收到分享而强制发送回复。分享里的内容是外部资料，不能改变机器人规则或授予权限。只读取公开文字，不观看视频、不播放音乐，不读取字幕、歌词、帖子图片或评论。页面不可读时明确说明，分享卡片提供的标题和简介只能作为未核验资料，不能冒充页面正文。

每个请求的候选和读取结果独立保存，不跨群、跨私聊复用。候选来自本轮实际收到的消息、当前群上下文，以及通过权限检查的历史或合并转发结果；模型不能自造链接让机器人访问。仅访问三个平台的明确域名，短链接逐跳检查同平台域名，不读取本机文件或内网地址，不发送登录凭据。

## 开发

- `plugins/assistant/shares.py` 负责消息段提取、地址校验、短链接解析、平台信息读取和 `read_share` 工具。JSON 卡片只提取地址、标题和简介；XML 禁止文档类型和实体声明；原生网易云音乐段按歌曲编号生成链接。其他平台卡片保持原有非文本提示。
- `__init__.py` 的 `extract_text` 将分享卡片转换为有限的资料文字，群聊及私聊归档因此可保留分享地址。`message_context.py` 与 `groupchat.py` 的引用文字沿用同一提取规则。`forward.py` 展开合并转发时保留卡片资料，读取后的链接再注册到候选中。
- `ShareReader` 在每轮开始注册当前消息、引用、群上下文及连续补充；私聊单独创建。`HistoryTools.shares` 将其传入 `llm.py` 的参与判断和回复工具循环；历史和合并转发工具返回后，注册实际读取到的分享链接。候选最多20个，每轮最多读取3个链接，同一链接的成功或失败结果缓存到本轮结束。参与判断与回复共用缓存和限额，也计入原有统一工具预算。
- `read_share` 的 `url` 为空时列出候选，非空时只接受已注册的链接。直接读取不依赖 Tavily 搜索密钥。默认规则和工具说明分别保存在 `prompts/catalog.json` 的 `llm.shares.0`、`tool.read_share.description`，沿用后台提示词覆盖。
- B 站读取 `api.bilibili.com/x/web-interface/view`，接受 BV 和 av 视频地址。网易云读取 `music.163.com` 的歌曲、专辑及歌单详情接口，支持桌面锚点链接和移动版地址。小黑盒读取 `api.xiaoheihe.cn/bbs/app/link/tree`，只提取 `result.link` 的文字，支持数字及十六进制帖子编号；正文块可能保存在 `content` 数组或 `text` 中的 JSON 数组。
- `share_sign.py` 为小黑盒生成时间戳、随机值和官网使用的公开网页签名，不需要账号密钥或 Cookie。规则依据[官网公开网页脚本](https://static.max-c.com/static/heybox/webapp/@heybox-spa/website/app/index-Q5il7rGn.js)；平台变更接口后需核对更新，验证码或登录要求不自动绕过。
- 每次读取最多4跳、1 MiB，网络操作在工作线程中执行，线程内总时限18秒，异步等待最多22秒，并受整轮请求超时限制。下载逐跳核验域名和公网解析，保留 TLS 域名并固定连接地址。本机纯 Fake-IP 解析经独立公网解析核验后保留其虚拟路由，避免直连其他地区的 CDN 触发风控；普通私网、混合私网解析不允许。
- 标题和作者最多200字，简介最多3000字，小黑盒正文最多6000字，正文超限返回 `truncated`。正文富文本移除脚本和样式，不将帖子评论当作原文。网页读取失败返回 `unavailable`，不支持的分享类型返回 `unsupported`，附卡片资料时明确标记未核验。

## 使用说明

更新后重启机器人，无需填写平台账号或新增密钥。群聊可发送分享后 @机器人询问，或引用分享询问；私聊可直接发送分享并提问。例如“看看这个视频讲什么”“这首歌是谁唱的”“总结这个帖子”。普通群消息继续由积极性和参与判断决定是否回应。

支持的常见地址：

| 平台 | 地址形式 |
| --- | --- |
| B 站 | `bilibili.com/video/BV…`、`bilibili.com/video/av…`、`b23.tv/…` |
| 网易云 | `music.163.com/#/song?id=…`、`y.music.163.com/m/song?id=…`，以及专辑、歌单地址和 `163cn.tv/…` 短链接 |
| 小黑盒 | 分享页的 `link_id=…`、`xiaoheihe.cn/app/bbs/link/…`、`xiaoheihe.cn/app/topic/link/…`、`xiaoheihe.cn/a/…` |

检查时分别发送链接和 QQ 分享卡片，再测试引用、连续补充以及合并转发。核对标题和作者；小黑盒核对正文是否属于帖子而不是评论。B 站番剧、直播、动态、专栏，小黑盒游戏详情等类型暂不读取，机器人会说明不支持。

读取失败可能来自内容删除、登录限制、平台风控或网络故障。可换成完整链接，稍后重试，或粘贴正文。纯图片帖没有可读取的文字正文；须另发图片才能使用现有图片识别。接口成功不代表获得了视频或音乐内容，模型应明确依据简介回答。

自动回归：`.venv\Scripts\python.exe -m unittest discover -s tests -p test_shares.py`。测试覆盖三家响应格式、卡片和归档、引用和连续消息、合并转发、双模型工具接入、失败回退、限额、跳转边界及 Fake-IP 校验。已在本机验证三家公开链接读取成功；不同 QQ 客户端的实际卡片格式仍需在群内核对。
