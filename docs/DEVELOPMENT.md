# 私人 QQ 小群 AI 机器人开发文档

更新日期：2026-10-12

本文描述当前消息处理与上下文实现。后台、任务、插件、迁移和诊断日志分别见对应模块文档。

## 1. 已确认的产品规则

采用 NapCatQQ + NoneBot2 + OneBot v11，首期运行在 Windows / Python 3.12。
用户显式 @机器人后直接表达需求，由模型理解聊天、分析、锐评等意图，并自行决定是否搜索。
不再按“分析、锐评、搜索”前缀进行业务路由，也不强制用户记住业务命令。

本地指令统一使用 `/` 前缀。所有成员可用 `/ping`、`/帮助`、`/help`。
群主、群管理员和配置 `BOT_OWNERS` 的机器人主人可用 `/清空`、`/清空 @某人`、`/清空 本群`；
仅主人可用 `/清空全部`。后两种批量操作需由原发起人在同群60秒内用 `/确认 确认码` 确认。
确认绑定机器人、群、用户、范围，单次有效，确认时重新鉴权。所有者由 BOT_OWNERS 指定，群主和群管理员通过平台实时查询确认；查询失败不授予群管理权限。
普通文本不执行命令，未知斜杠指令不交给模型。权限帮助与用法见 README。

群消息统一交给 GroupConversation：显式@直接处理，其余消息合并后由模型判断参与；忽略自身消息。私聊另行校验好友/共同群资格。
采集机器人已加入的群内全部新消息至 SQLite；保留引用关系与消息身份。当前或引用图片按需附给支持视觉的模型，语音和附件暂不识别，原图不写入聊天档案。

## 2. 模型与搜索

配置 `LLM_PROVIDER=deepseek|openai` 选择一家服务商。两套 API Key 和模型 ID 分开配置，切换后重启；没有隐式降级或重试。

| 服务 | 接口 | 协议 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/chat/completions` | Chat Completions；`thinking.type` 由 `LLM_THINKING_ENABLED` 控制，默认关闭 |
| OpenAI | `https://api.openai.com/v1/responses` | Responses；`store=false`；工具轮次保留返回的推理条目 |
| Tavily | `https://api.tavily.com/search` | Bearer Token，basic 搜索，只获取摘要 |

模型 ID 无默认值，必须填写账户可用、支持所用协议和函数工具的模型。启动检查当前服务商模型配置；搜索 Key 可缺省。
配置细节及所有默认限额见根目录 `.env.example`。原预留 `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL` 已被分服务商字段替换。

统一系统提示词指导模型自行理解意图：聊天简洁自然；分析给出结论、依据、假设、反例和建议；锐评围绕提供的内容，默认200字以内。
这是模型提示约束，不是独立分类器，也不对“锐评”输出做程序级200字截断。全局输出有硬上限。

模型通过统一工具循环使用历史、搜索、表情包及当前可用的本地插件和任务工具。程序校验工具名称、调用 ID、JSON 参数、权限及调用预算。
默认统一工具流程最多执行6步，其中联网搜索最多2次；读取每步结果后再决定下一步。多工具返回的恢复规则见“工具调用顺序”。没有历史工具的独立搜索流程最多2次搜索，可在一次返回中按顺序执行多个合法搜索，但总数不得越限。
搜索服务只收到模型生成的独立查询，不收到整个会话；模型本身会收到该用户的短期上下文。
搜索 Key 缺失时不提供工具，同时在系统提示词里明确说明无法联网。

每条搜索摘要最多1500字符，URL仅接受合法HTTP(S)，结果分配本次固定编号。搜索资料以工具数据形式传入，不能改变系统规则。
联网回复直接解释搜索结果，不展示参考链接、来源列表或引用编号；仍需依据资料回答并说明不确定性。
`render_reply` 不追加来源，存在搜索结果时清除正文中的数字引用和 HTTP(S) 链接，Markdown 链接保留文字；完整输出预算用于正文。仍需实测回答质量。
搜索失败/空结果直接返回明确状态，不让模型伪装搜索成功；已获得来源但后续失败时提示未完成总结及稍后重试，不展示来源，不保存为成功会话。

## 3. 工程结构

独立群插件由 `plugins/extensions/manager.py` 注册与分派，配置和隔离数据位于 `data/plugins.json`，复用模型工具循环、命令权限与诊断日志。首个定时消息插件支持自然语言提议和管理员确认，设计、开发接口与使用步骤见 [插件体系](PLUGINS.md) 和 [定时消息](SCHEDULE.md)。

```text
bot.py                         # 入口、隐私日志、插件注册
plugins/assistant/
  __init__.py                  # 显式@、文本提取、启动关闭、清理任务
  config.py                    # 配置与启动校验
  prompts.py                   # 自然意图提示词与搜索工具定义
  llm.py                       # 两家模型协议、受限工具循环、输出格式化
  search.py                    # Tavily与结果规整
  http.py                      # HTTP异常映射、安全用量日志
  memory.py                    # 完整问答、过期、会话锁
  limits.py                    # 冷却、并发、去重
  service.py                   # 消息工作流与发送后保存
 tests/test_assistant.py        # 本地模拟测试
```

入口加载插件后显式调用 `setup()`，导入核心模块不会启动网络服务，便于独立测试。
启动时创建共享HTTPX客户端，关闭时释放客户端并取消清理任务。每分钟清理过期会话和限流记录；锁表引用计数归零即释放。

## 4. 消息工作流

```text
所有已加入的群 / 忽略自身 / @直接处理，普通消息进入参与决策
→ 提取文本 / 消息ID去重
→ 本地帮助和ping / 空输入和长度提示
→ 待处理数量上限 / 用户冷却（清空免冷却）
→ 会话锁
→ 清空，或获取全局额度
→ 模型自主回答 / 搜索工具循环
→ 按纯文本分段发送
→ 全部发送成功后保存可见问答
```

会话键为 `(bot_id, group_id, user_id)`；去重键为 `(bot_id, group_id, message_id)`。
会话保留完整轮次，不保存工具过程或推理内容。默认8轮、12000字符、30分钟失效；超限从最旧轮次删除。
指令不受普通聊天冷却限制；部分指令提示会经模型润色，任务与后台入口结果原样发送。单人清空使用目标会话锁。批量清空阻止新会话进入并等待范围内已有会话完成，超过3秒不删除并提示重试；成功后不会有旧请求写回。
并发额度覆盖整个模型/搜索工作流，限制搜索和模型合计资源。发送失败不重试，不保存部分答案。

文字输出通过 `MessageSegment.text` 发送，模型生成的 CQ 代码不会变成可执行消息段；引用和表情图片由程序创建对应消息段。
鉴权失败、HTTP限流、网络超时、错误JSON、空回复、格式错误和过长输出均有受控处理。
普通业务日志只记录请求ID、模式auto、耗时、状态码、token计数及异常类型；不写请求正文、响应正文或授权头。独立模型诊断日志默认开启，记录动态上下文、工具参数与结果、参与判断及发送状态；固定提示词折叠、凭据过滤和开关配置见 [诊断日志](LOGGING.md)。

## 5. 验证与真实联调

本地执行命令见 README。自动测试覆盖：

- 配置校验、原始@消息判断、任意群接入、自身消息过滤。
- 自然语言原样进入模型、辅助命令、空输入、长输入。
- 两家模型工具协议、OpenAI推理条目回传、搜索参数校验和次数上限。
- 搜索失败/空结果、模型失败时提示未完成总结且不展示来源、非法JSON和鉴权/限流错误。
- 会话隔离、完整轮次裁剪、过期、清空竞态、锁超时和清理。
- 去重、冷却、并发许可释放、发送失败不保存、不重试、长回复与引用。

本地测试不访问真实服务。上线前人工验证以下场景：

| 场景 | 通过标准 |
| --- | --- |
| 任意已加入的群显式@后ping | 仅收到一次pong |
| 自身消息 | 不触发回复 |
| 未@、引用无@ | 根据积极性和话题判断参与，可能调用模型 |
| 自然聊天和连续追问 | 上下文正确，用户/群互不串话 |
| “帮我分析…”和“吐槽一下…” | 无需命令，回答符合意图 |
| 自然提问实时信息 | 模型自行搜索，直接解释结果且不附参考链接 |
| 分别配置DeepSeek/OpenAI | 两家真实账户均可完成聊天与工具调用 |
| 清空与正在生成交叠 | 清空成功后不再出现旧历史；超时明确提示重试 |
| NapCat断线、业务进程重启 | 能重新连接，重启后最近问答与长期认知从SQLite恢复 |

## 6. 常驻部署

真实收发与模型联调通过后再配置 Windows 任务计划程序，分别管理业务服务与 NapCat：

- 程序：`C:\path\to\QQBot\.venv\Scripts\python.exe`
- 参数：`bot.py`
- 工作目录：`C:\path\to\QQBot`
- 按各进程需要选择登录触发或启动触发，设置失败重启；NapCat登录态失效仍可能需要人工登录。

本项目采用本机部署，机器人和后台仅监听 127.0.0.1。NapCat 登录状态及收发能力需在启动后验证；不提供局域网或公网后台访问。

## 7. 功能边界

聊天模型通过已注册工具读取历史、搜索、处理表情及申请本机任务，不直接获得任意系统命令执行能力。本机开发执行由任务模块管理权限、审批及执行队列，见 [本机自主任务](TASKS.md)；定时消息见 [定时消息](SCHEDULE.md)。不自动切换模型服务商。

## 本地人设与风格配置

`personas/默认.txt` 和 `styles/默认.txt` 分别保存默认人设及表达偏好，各限制4000字符。
两个文件夹中的其他 `.txt` 文件是可切换选项；群管理指令只保存名称，不能从聊天写入提示词正文。
启动校验默认文件，每次生成重新读取，生成期间使用固定快照；群选择按群保存，未选择时及私聊使用默认。
配置作为带边界说明的JSON偏好注入统一系统提示词，两家模型共用，不增加模型工具权限；切换后历史仍保留。
后台可维护正文，群内可查看选项名称并由有权限的管理者切换。读取错误只记录异常类型并返回通用错误，不把配置文本发送到QQ或写入日志。
配套模板的设计、文件结构、切换及验证说明见 [人格与说话方式模板](PROFILES.md)。

## 长期记忆实现

`longterm.py` 用SQLite的 messages/turns/facts/profile_cursor 表保存消息、完整问答、自述认知和提取进度。
前置事件处理器在@匹配前落库，因此所有已加入的群中未@的消息也被保存；普通消息进入主动参与判断。
非文本只存类型及占位符。程序发出的回复带关联用户，单用户清空同时删除相关机器人回复。

认知在后台按用户批处理，只向模型发送该用户的发言，不提供搜索工具。输出总体认知、私聊印象或群内四类认知的自然语言片段，由程序检查长度和原文引用；片段按来源独立保留，读取时先执行公开审核，再合并为一段总体认知或当前会话印象。后台维护者确认的总体认知、私聊段落及群内分类分别固定保留。
提取在会话锁外请求模型，写回前核对游标和源消息是否还存在，避免清空或手动纠正后旧任务写回。
消息原文、问答和认知不进入普通业务日志；开启模型诊断时，会在独立诊断文件保留实际发送给模型的动态内容。任何日志均不作为长期记忆导入。

短期 TTL 控制问答自动恢复的时间范围，过期不删除长期档案。清空必须同时删除数据库，不仅删除缓存，批量清空覆盖磁盘上未加载的用户。
检索采用最近1000条内的中文二字片段/英文词匹配，不依赖向量库；整库历史长期保留，非语义检索。
各项指令权限、批处理限额及备份说明见README。

群参与实现见 `groupchat.py`，群设置见 `group_chat.json`。兴趣仅本地设置；`/积极性` 修改复用本地QQ权限等级。普通群消息按群合并后判断参与，模型话题状态保存在内存，重启后重新从历史判断。

### 持久问答的有效期

持久问答恢复遵循 `session_ttl_seconds`，只自动载入有效期内的轮次，继续受轮数和字符数限制，并为历史问答保留 Unix 时间。过期仅影响自动上下文，不删除记录；明确追问仍可通过相关历史检索读取。任务摘要仅在回复入口注入，群聊参与判断不重复携带。

## 群聊话题与命令结果上下文

### 设计

本次问题优先根据明确引用与最新相邻群聊确定指代。旧个人问答仅提供背景，不默认代表当前话题；指代不明时简短澄清。命令的实际返回结果应供后续问答获知，历史命令不得自动重放。

### 开发

`LLM.reply` 将旧问答作为有边界的 JSON 历史背景，随后附加当前记忆与群聊上下文，最后放本次输入。参与判断输出 `reply_focus`，经 `GroupConversation.respond` 限长后与触发消息 ID 一起传给回复阶段；回复阶段核对原消息，不将该线索视为操作授权。

`Assistant.handle` 在命令结果成功发送后保存命令与实际发送文本至会话记忆及持久问答记录；发送失败不保存成功问答。命令结果包括拒绝、待确认和完成状态，不能一概视为执行成功。清空命令不会恢复旧记录，但本次清空结果可作为新记录保留。

### 使用与验证

更新代码后重启机器人。先创建并确认一个定时任务，再让群成员切换到其他话题，随后 @机器人询问“真的吗”；回复应围绕新话题，歧义未解时澄清。直接询问之前命令结果时应能获知完成或拒绝状态。自动验证见 `tests/test_topic_context.py` 与 `tests/test_groupchat.py`；测试验证请求结构与数据流，真实模型的指代判断仍需群聊验收。

## 工具调用顺序

### 设计

消息回复及参与判断按步骤使用工具，先取得实际结果，再决定后续操作。一次模型返回包含多个调用时，只执行首个，其余明确标记为未执行，由模型结合结果按需重新请求；不得将未执行操作当作成功，也不自动重放有副作用的操作。

多调用恢复不增加执行预算或绕过权限、发送去重、图片识别及内容记忆要求。整批调用必须能通过独立编号对应结果，编号无效时应在任何操作发生前拒绝。

### 开发

`LLM.investigate` 先核验整批 `call_id` 为非空字符串且不重复，再按原有工具分派执行首个调用。其余编号回传 `not_executed`，原因是 `sequential_tool_calls`；每个调用均按 DeepSeek 或 OpenAI 协议获得对应结果，并保留模型的原始输出和推理条目。原图在整批工具结果之后附加。

统一工具预算仍按实际执行步骤计数，延后调用不占用步骤，也不会自行执行。下一次模型请求重新确定可用工具；达到预算后关闭工具，要求完成回答。诊断日志用 `tool_skipped` 记录未执行调用，与实际工具执行记录区分。

### 使用与验证

更新后重启机器人即可生效，用户无需在提问中要求模型限制工具数量。可通过历史查询、连续检索或表情选择验证最终回复；诊断日志出现 `tool_skipped` 表示模型提出的后续操作尚未执行，不代表已发送、收藏或创建任务。

自动验证见 `tests/test_tool_calls.py`，覆盖两家服务商的多调用恢复及结果对应、参与判断保持沉默、执行预算、重复发送保护、无效编号在副作用之前拒绝，以及最终回复正常发送和保存。

运行配置可在本机后台“设置”维护，生效范围及模型兼容规则见 [后台设置](SETTINGS.md)。
