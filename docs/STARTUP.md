# 本机联合启动

## 设计

Windows 上一次启动操作即可拉起本机后台、消息接入服务与机器人，并打开后台页面。后台独立运行，停止机器人后仍可导入数据。消息接入服务已监听时直接复用，避免每次重启机器人都重复启动。登录仍由接入服务处理，端口监听不代表账号已登录。停止机器人不会停止消息接入服务或其他 QQ。

## 开发

`start.bat` 调用 `start.ps1`，后者先通过 `scripts/admin.ps1` 重启本项目后台并打开浏览器，保证代码更新生效，后台不可用则报告失败；再通过 `scripts/napcat.ps1` 调用 `scripts/startup_config.py` 通过 python-dotenv 读取 `.env` 中的启动字段、探测本机 TCP 端口并启动 NapCat，再沿用原有机器人重启流程。NapCat 启动器的工作目录为启动文件所在目录，支持 `.bat`、`.cmd` 和 `.exe`，批处理通过系统 cmd 执行。脚本使用 UTF-8 BOM，兼容 Windows PowerShell 5.1 的中文解析，代码行尾为 CRLF。

首次启动交互获取路径，验证后保存至根目录 `.env` 的 `NAPCAT_LAUNCHER`；已有配置直接读取。相对路径以项目根目录为基准，支持环境变量。路径不能含百分号（环境变量展开后）、双引号、换行或感叹号。配置不接受任意命令字符串或附加参数；如需参数，可指向用户自己的启动批处理。

默认探测 `127.0.0.1:6099`。端口被占用时直接复用，不验证占用者身份，因此该端口必须专属于 NapCat。未监听时拉起启动器，最多等待 30 秒；失败则保留 NapCat 窗口并停止本次机器人启动，不关闭已运行机器人。再次启动会重新检查端口。NapCat 控制台用于扫码登录，保留可见窗口。

`.env` 被 Git 忽略，随私有迁移包迁移；新机器需核对并修改启动路径。读写启动配置不会输出其他字段或密钥。

## 使用说明

1. 安装 NapCat，并配置连接本项目的 OneBot WebSocket 客户端。
2. 双击 `start.bat`，首次按提示输入实际启动文件完整路径，例如 `D:/NapCat/launcher.bat`。路径含空格或中文均可。
3. 在 NapCat 窗口或 WebUI 登录 QQ；需要管理员授权时，由用户处理系统提示。
4. 等待机器人启动，在 QQ 中发送 `@机器人 /ping` 验证连接。机器人所有者可发送 `/后台` 或“后台入口在哪里”查询入口；私聊直接发送，群聊需 @机器人。普通成员、群管理员和群主均不能查询，除非同时配置为机器人所有者。
5. 需要只运行后台时，执行 `.\.venv\Scripts\python.exe admin_server.py`，浏览器打开 `http://127.0.0.1:8090`。

也可以直接编辑 `.env`（字段示例见 `.env.example`）：

```dotenv
NAPCAT_LAUNCHER='D:/NapCat/launcher.bat'
NAPCAT_PORT=6099
```

`NAPCAT_LAUNCHER` 是文件路径，不是安装目录。建议使用正斜杠，路径含空格或井号时使用单引号包围。`NAPCAT_PORT` 应填写实际的本机 NapCat 监听端口，缺省为 6099，通常是 WebUI 端口，不要填写机器人的 8080 端口。关闭 WebUI 时需另选 NapCat 实际开放的本机端口。

修改路径或端口后重新双击启动即可。若未检测到监听，检查 NapCat 窗口中的报错、管理员授权、端口和绑定地址；启动耗时超过 30 秒时，待其就绪后重试。端口已就绪但机器人不回复时，检查 QQ 登录、WebSocket 客户端地址和 Token，端口检查不能代替这些验证。

自动检查：`.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_startup.py -v`。测试使用临时文件、回环监听和模拟启动，不启动真实 QQ 或 NapCat。
