# DSH 聊天执行

## 设计

聊天由 DSH 主导回答与工具调用，根据本次会话中真实可用的能力完成检索、任务查询、插件操作与表达。机器人负责身份、权限、状态、发送事务和持久记忆，模型的成功描述不能代替执行结果。后台任务继续使用审批、排队和结果验证流程。

客户端接入依据项目所需运行能力，不绑定具体版本号，也不要求客户端和随附运行时的版本字符串相等。升级后能力仍满足要求即可继续使用；缺少必要模块或接口时说明具体缺项，不将版本变化本身作为失败原因。

主执行会话按机器人账号、群或私聊对象持续保存，跨轮保留工具结果及未完成工作的上下文。草稿与平台已发送消息分开理解；发送成功、失败及过期状态作为模块事件提供。每轮重新核验身份与工具权限，清除历史或权限范围变化后建立新的执行上下文。聊天只开放已注册业务工具，不提供任意本机命令或文件操作。

普通群消息先由辅助 API 逐条判断话题归属及是否回应机器人，由程序执行固定人数和续话门槛。直接呼叫跳过参与门槛；普通话题判断失败时保持沉默。观察间隔独立配置，主回合可以选择静默并维护记忆，详见[话题策略](TOPICS.md)。无新消息不自主唤醒；同发送者补充阻止旧副作用和发送，无关群消息不丢弃当前工作。

工具次数、Token 或费用预算耗尽后，停止执行新工具，允许在剩余处理时间内仅根据已有结果完成一次收尾，准确说明尚未完成的事项。收尾不能继续查询或产生工具副作用；时间耗尽则停止本轮处理。错误提示应区分资源上限、超时、图片能力和其他执行失败，不把所有运行错误归因于安装或模型配置。

客户端浏览记录按机器人账号、群或私聊对象汇总为连续会话，保留正常完成的模型回合及工具结果。浏览记录不作为机器人后续请求的历史来源；生成结果不代表平台发送成功。后台试聊不写入客户端会话。

聊天执行所需图片保存在各自执行会话的数据目录，图片写入不依赖客户端根目录的权限修改。客户端展示图片采用独立补写；展示失败保留待补写记录，不中断正常聊天。已有执行会话引用的旧图片按需读取并迁入当前会话。

自然表达遵循当前人设和上下文，减少机械开场、强行追问和重复总结。分条围绕完整意思，保护代码与列表，保留既有发送停顿，完整分包而不按总字数裁切。后台的人设试聊使用虚构输入，无真实聊天副作用。

聊天提示词区分当前明确委托与程序可信上下文提供的有效持续授权。自主探索仍受目标、能力、资源范围、预算、有效期与停止条件约束；兴趣和只读操作都不产生任意访问权限。当前未开放宿主机通用操作，也未增加持续授权配置或自主唤醒机制，这些提示词边界不构成实际授权。

## 开发

- `plugins/tasks/desktop.py` 从 Windows 安装信息与常见安装路径定位客户端，读取 ASAR 安装结构，确认可执行文件、Harness 包和 CLI 入口。`desktop_check.mjs` 通过客户端自身的 Node 运行时加载桥接实际依赖的模块，检查 agent、消息、原生会话、持久化及图片附件接口；检查不读取个人配置、不调用模型、不传递 API 密钥。成功结果按安装路径、归档与可执行文件的修改时间和大小缓存，文件更新后重新探测。通过客户端 Electron 的 Node 模式执行随附 CLI，不调用全局 npm 包、不修改个人安装。`InstallationError` 提供受控安装及能力诊断，聊天入口转换为业务提示；子进程原始输出不直接发往 QQ。
- `plugins/assistant/dsh.py` 的 `Chat` 在每次回复创建 `Turn`，使用临时启动配置及按机器人/会话隔离的持久 DSH 目录 `data/agent/<bot>/<scope>/<generation>`。同一会话串行恢复，调用原生 `agents.create/resume` 及 `sessions.flush`；代际由权限范围和清除历史标记决定。`ContextVar` 隔离并发回合；超时、取消和结束后关闭自己的进程树并清理临时目录。
- `dsh_bridge.mjs` 通过 Cordis 注册本轮业务工具，关闭全局工具及子代理入口，使用 DSH 原生工具循环。首轮将已组装上下文标注历史角色与当前请求后交给 DSH；之后只回传新工具结果，避免重复执行。图片先由 Python 按下载限制验证，再交给附件服务。
- `attachment-local` 的 `dshHome` 固定为执行会话自身目录，正式聊天的规范化图片保存在 `data/agent/<bot>/<scope>/<generation>/attachments/v1`，试聊使用临时目录。`dsh_attachments.mjs` 在原生读取报告对象缺失时，按实际引用从客户端旧附件目录读取、核验并迁入本会话；原生模型请求的图片转换缓存也保存在执行目录。
- Python 与桥接进程按 `call_id` 交换整批工具调用及对应结果。`LLM.investigate` 委托 `tools.py` 的注册表执行；独立只读调用并行，写操作构成顺序屏障。参数、作用域、审批、图片哈希和发送去重由原模块校验；原图在对应工具结果之后附加。查看图片不强制保存描述，不再封锁其他工具。
- `budget.py` 维护单次唤醒共享的工具次数、时间、Token 和可选费用预算，每次工具结果反馈剩余资源。默认 96 次工具调用、1000000 Token，仍受完整请求超时约束。每次模型调用的输入用量包含持续会话历史及缓存输入，按本轮调用累计。费用根据维护者配置的每百万 Token 单价保守估算，缓存输入按普通输入计价；0 表示不启用费用预算。Token/费用在模型报告用量后更新，`tools.py` 禁用后续工具并附加收尾指令；桥接仅放行一次无工具收尾，超时仍立即停止。已发出请求及收尾可能跨过阈值，不能视为服务商账单硬限额。
- 桥接通过结构化错误码区分预算耗尽、步骤上限、处理超时及图片能力不足。原生回合将异常包装为通用错误时仍保留受控停止原因；Python 仅发送固定提示，不把底层异常正文、请求内容或凭据发到 QQ，详细诊断沿用本机脱敏日志。
- `response.py` 的 `set_response` 接收回应/静默/复读、引用与话题状态。复读发送仍校验当前候选、冷却及实际发送去重；引用只接受已知消息。`events.py` 按机器人和会话保存最近 32 项模块状态，自动注入主回合；`Store.save` 产生任务状态事件，插件切换及发送结果在各自执行入口写入。任务终态通知由同一 `Chat` 主 agent 处理，可静默；后台事件不挂载需要新用户授权的任务修改或插件执行工具。审批请求仍走原有主人确认流程。
- `dsh_view.mjs` 使用客户端原生 JSONL/Zstd 持久化接口追加浏览记录。会话标识按机器人账号及正负会话范围区分；每次持有原生跨进程写锁，重新读取已有记录并续接回合编号，完整校验生命周期后整批写入。记录先原子写入客户端目录内的 `qqbot-pending` 队列，依据记录标识去重；客户端占用写锁时保留队列，机器人独立工作循环初始每 15 秒尝试补写，持续占用或同类错误时按 15、30、60、120、240、300 秒退避，恢复后回到 15 秒；队列跨重启保留，重复补写不重复展示。展示保留用户输入、图片、模型消息及原生工具事件，不复制系统提示词和历史上下文。队列记录本回合附件来源目录；补写会话前将用户输入和工具结果中的规范化图片核验并复制到客户端 `attachments/v1/objects`，以完整临时文件及硬链接原子发布，不调用客户端目录的 `chmod`，不覆盖已有对象。图片和会话写入均成功后才移除队列，失败或取消回合不进入镜像。原生写锁占用与创建竞争单独归类为等待，补写工具输出带 `QQBOT_VIEW_SYNC` 前缀的计数及异常类型摘要，只有真实失败才返回非零状态。`ViewSync` 按状态变化提示：占用与恢复各输出一次普通信息，同类真实错误仅警告一次；`dsh_view_sync` 诊断事件保留每次检查的摘要。聊天回合自身无法保存浏览记录时仍记录 `dsh_view_save_failed`；客户端异常正文不写入日志。
- `modules.py` 汇总任务和插件能力，插件启停复用现有鉴权入口；历史、表情、分享等仍使用各模块现有执行器。`chat.modules` 提示查询真实状态并区分待审批、排队、成功和失败。
- 辅助话题判断、安全审核与后台修改建议使用辅助模型 API；认知维护、参与方式和任务通知由主 DSH agent 决定。正式聊天无 API 直连回退分支。
- 诊断标准输出与标准错误不直接进入日志；结构化聊天上下文、回复及用量沿用现有诊断开关与脱敏机制。

## 使用说明

安装 Windows DeepSeek Harness 客户端，具备所需运行能力即可，无固定版本要求。配置 `.env`：

| 配置 | 含义 |
| --- | --- |
| `DSH_PACKAGE_DIR` | 留空自动查找；也可填写 `D:\DeepSeek Harness` 这样的客户端安装目录或客户端可执行文件路径 |
| `DSH_MODEL` | 聊天与任务模型，默认 `deepseek-flash` |
| `DSH_OUTPUT_TOKENS` | 主聊天单次输出额度，默认 16384，与辅助 API 分开 |
| `WAKE_INTERVAL_SECONDS` | 群消息话题观察最短间隔，默认 8 秒 |
| `DSH_VIEW_HOME` | 客户端数据目录；留空依次使用进程的 `DSH_HOME` 或当前用户 `~/.dsh` |
| `AGENT_MAX_CALLS` / `AGENT_MAX_TOKENS` | 每次唤醒共享工具次数与 Token 预算 |
| `AGENT_MAX_COST` | 可选费用上限，默认 0；需配输入与输出单价 |
| `AGENT_INPUT_PRICE` / `AGENT_OUTPUT_PRICE` | 每百万 Token 单价，币种需与费用上限一致；不自动获取价格 |
| `DEEPSEEK_API_KEY` | DSH 使用的官方 API 凭据 |
| `LLM_PROVIDER` 及对应模型配置 | 辅助处理所用服务商及模型，不改变 DSH 主聊天模型 |

机器人启动前检查安装、必要模块与接口及密钥，不按版本号拒绝客户端。能力缺失时提示具体模块或导出；检查超时或无法启动运行时也分别说明。此检查验证桥接依赖能被加载，不能代替真实模型、工具及会话行为验证；底层接口语义变化仍需适配。更新代码或运行参数后重启机器人及后台。默认模型标识采用当前客户端目录中的 `deepseek-flash`，支持图片。图片输入前检查客户端模型目录能力；纯文本或未知模型不再静默丢弃图片，而是明确报错。显式配置旧标识 `deepseek-v4-flash` 的部署需改为 `deepseek-flash`。

验证时检查普通聊天、同一问题的追问、能力查询、获准的插件启停与任务状态查询。只发图片或拍一拍不应附加空文字。后台“提示词管理”可用人设对比试聊验证措辞与分条，规则及场景见 [人设](PROFILES.md)。

自动回归使用 `python -m unittest discover -s tests -q`，覆盖权限、空回复、分条、图片准备、回合取消、工具结果传递和试聊无写入。实际 QQ 收发与模型语气仍需在部署后观察；模型输出存在随机性。

`tests/test_desktop.py` 覆盖任意版本字符串及版本不一致仍可接入、必要入口缺失、具体能力诊断、升级后检查缓存失效和诊断输出隔离。`python -m tests.smoke_agent` 使用真实模型验证当前安装的图片输入、持续会话恢复与多工具调用，不发送 QQ 消息。

`tests/test_dsh_budget.py` 使用已安装客户端运行时与确定性假模型驱动正式桥接，不调用真实 API，覆盖累计 Token 超限后的收尾、费用与工具次数耗尽、禁止重复收尾、超时及错误提示脱敏。`tests/test_agent.py` 验证工具调度在预算耗尽后不执行查询，并提供无工具收尾指令。

出现资源预算提示时，在本机模型诊断日志中检查同一请求的 `dsh_usage` 及 `dsh_error`。较长的持续会话可能经过少量调用就耗尽 Token；需要更多查询时可在后台设置调整 `AGENT_MAX_TOKENS`，并核对费用与完整请求超时。通用执行失败提示表示查看同请求的诊断事件；安装校验及图片能力错误会分别提示，不应仅凭通用提示重装客户端。

### 手动重置执行会话

核心规则或提示词调整后，可在后台设置页点击“重置全部 agent 会话”并确认。下轮按当前规则建立新执行会话，不恢复旧草稿和工具上下文；仍会读取获准聊天档案、认知和任务状态。所有机器人账号、群聊和私聊均受影响。已执行操作、独立后台任务及客户端浏览记录保留，未保存草稿不会生效。

全局版本保存在 `data/agent-events/all.epoch`，与既有单会话历史清理版本共同决定执行目录。重置可在机器人运行时进行，无须删除快照文件；旧模型调用不保证即时终止，后续有效性检查阻止过期操作和回复。首次部署本功能需重启机器人与后台，之后点击重置不需要重启。

### 在客户端查看

重启机器人后，正常完成的新聊天回合会追加到客户端数据目录的 `sessions` 中，归属本项目工作目录。在 DSH 客户端的会话列表中查找“群名（群号）”或“昵称（QQ号）”。名称从平台联系人缓存读取，缺失时使用历史消息的平台名称，再缺失则显示“群名待同步”或“昵称待同步”；已有会话在下次正常完成的回复追加时更新标题。标题不改变内部机器人账号隔离。同群不同发送者进入同一会话，每次提问标明发送者和请求编号；不同机器人账号、不同群和不同私聊彼此隔离。列表未刷新时重新打开会话列表，必要时重启 DSH 客户端。客户端若持有当前会话写锁，新记录会暂存在待同步队列；关闭或离开该会话释放写锁后，机器人会自动补写，再打开即可查看。持续占用期间仅提示一次普通信息，不重复输出警告；自动检查间隔最长 5 分钟，正常完成的新聊天回合也会尝试补写。占用期间不强制解锁，不影响机器人的正常回复。

展示在模型完成后追加，不是实时流式镜像。保留输入图片、工具调用/结果和模型生成内容；失败或取消回合不追加。此处显示的是生成记录，平台发送结果仍以 QQ 和机器人档案为准。在 DSH 客户端继续聊天不会向 QQ 发送消息，客户端续聊产生的内容也不会回灌机器人上下文。

默认本机目录为 `%USERPROFILE%\.dsh`；若客户端使用自定义数据目录，在后台“设置 → 聊天与任务执行”填写相同目录，或配置 `DSH_VIEW_HOME` 后重启机器人。目录应填写数据根目录，而非 `sessions` 子目录或客户端安装目录。

该配置只决定客户端浏览副本位置。聊天读取和新增图片使用项目内的执行附件目录，无须手动指定新路径。遇到客户端根目录 `chmod` 的 `EPERM` 错误时，部署当前版本并重启机器人即可避开聊天图片写入对该操作的依赖；客户端目录仍需允许普通文件写入，若浏览补写失败会保留队列，待权限恢复后自动重试。保留现有执行目录和客户端附件，可继续读取已保存的历史图片；不要在待补写记录完成前清理对应执行目录。

`tests/test_dsh_attachments.py` 使用原生附件及会话服务验证客户端根目录拒绝 `chmod` 时的独立保存、旧图按需迁入、用户与工具图片收集、并发去重、对象校验及补写失败后的恢复，不调用真实模型。

此功能只记录启用后的新回合，不回填此前已清理的临时执行记录；后台人设试聊、辅助模型操作及自主任务的独立运行日志不进入这些聊天会话。记录保存在 DSH 数据目录，连同待同步队列独立于机器人私有迁移包和日志保留天数；迁移或清理时应通过 DSH 单独管理。

执行快照 `data/agent` 是本机 DSH 运行状态缓存，不纳入机器人迁移包；换机从已迁移的真实聊天、任务台账和模块事件重新建立执行会话。客户端浏览镜像仍由 DSH 单独管理。`data/agent-events` 随私有包迁移，按事件编号合并且保持账号隔离。自动测试见 `tests/test_agent.py`；`python -m tests.smoke_agent` 使用真实 API 验证原生恢复与多工具调用，不发送 QQ 消息。

### 浏览记录恢复

客户端占用属于正常等待，无需重建会话；释放写锁后等待自动补写即可。真正的补写失败会警告异常类型并保留队列，同类错误持续存在时不重复警告；可在模型诊断日志的 `dsh_view_sync` 事件中查看写入数量、占用数量、异常类型及下次检查间隔。需要重新生成浏览会话时，使用客户端内置运行时执行 `plugins/assistant/dsh_view_sync.mjs <数据根目录> <项目绝对路径> recover <原会话标识...>`；运行环境须提供 `QQBOT_DSH_PACKAGE` 并启用 `--expose-internals`，与正常补写启动方式一致。操作前备份会话目录与待同步队列，避免并行执行恢复。恢复通过原生只读接口读取旧会话，建立新副本并补写队列，不删除旧会话或解除客户端写锁。

`qqbot-views/<项目摘要>.json` 保存逻辑会话到新浏览副本的映射，后续补写沿用该映射；映射与客户端记录一起保存，不改变机器人执行会话的标识或重置代际。原生占用恢复回归覆盖旧会话持锁、积压补写及新消息继续追加；`python -m tests.smoke_agent` 还验证两轮不同图片识别及恢复后的历史记忆。

### 连续背景追加

首次建立执行会话时补充历史问答，恢复已有会话时不重复追加该背景。认知、群聊、任务与模块事件由 `service.py` 分项组装，`dsh_context.mjs` 比较上轮快照摘要，只提供变化内容；消息按会话与来源编号比较，修改再次提供，字段删除以空值明确清除。摘要随原生用户事件来源保存，进程重启可恢复；重置后的新会话重新加载当前背景。系统提示每轮刷新，当前请求及当前图片始终输入。窗口外历史仍可通过工具查询。图片留档见 [聊天图片](CHAT_IMAGES.md)。
