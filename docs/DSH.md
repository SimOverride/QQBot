# DSH 聊天执行

## 设计

聊天由 DSH 主导回答与工具调用，根据本次会话中真实可用的能力完成检索、任务查询、插件操作与表达。机器人负责身份、权限、状态、发送事务和持久记忆，模型的成功描述不能代替执行结果。后台任务继续使用审批、排队和结果验证流程。

每次聊天使用独立执行会话，历史由机器人已确认的上下文提供；未发送回答不得成为后续真实聊天记忆。执行期间可更新可用工具，禁用模块即时退出可调用范围。聊天只开放已注册业务工具，不提供任意本机命令或文件操作。

自然表达遵循当前人设和上下文，减少机械开场、强行追问和重复总结。分条围绕完整意思，保护代码与列表，不调整既有发送停顿。后台的人设试聊使用虚构输入，无真实聊天副作用。

## 开发

- `plugins/tasks/desktop.py` 从 Windows 安装信息与常见安装路径定位客户端，读取 ASAR 元数据，校验客户端及随附 Harness 均为 `0.2.1-rc.2`。通过客户端 Electron 的 Node 模式执行随附 CLI，不调用全局 npm 包、不修改个人安装。
- `plugins/assistant/dsh.py` 的 `Chat` 在每次回复创建 `Turn`，使用独立临时工作目录和 DSH 配置。`ContextVar` 隔离并发回合；超时、取消和结束后关闭自己的进程树并清理临时目录。
- `dsh_bridge.mjs` 通过 Cordis 注册本轮业务工具，关闭全局工具及子代理入口，使用 DSH 原生工具循环。首轮将已组装上下文标注历史角色与当前请求后交给 DSH；之后只回传新工具结果，避免重复执行。图片先由 Python 按下载限制验证，再交给附件服务。
- Python 与桥接进程通过带前缀的 JSON 行交换工具请求和结果。`LLM.investigate` 负责已有参数校验、过期判断、预算和业务执行；DSH 负责下一步模型决策。每模型步骤至多执行一个业务工具，同批其余调用返回未执行，模型可重新决定后续操作。
- `modules.py` 汇总任务和插件能力，插件启停复用现有鉴权入口；历史、表情、分享等仍使用各模块现有执行器。`chat.modules` 提示查询真实状态并区分待审批、排队、成功和失败。
- 参与判断、认知提取、安全审核、任务结果改写与后台修改建议继续使用辅助模型 API。正式聊天无 API 直连回退分支。
- 诊断标准输出与标准错误不直接进入日志；结构化聊天上下文、回复及用量沿用现有诊断开关与脱敏机制。

## 使用说明

安装 Windows DeepSeek Harness 客户端 **0.2.1-rc.2**。配置 `.env`：

| 配置 | 含义 |
| --- | --- |
| `DSH_PACKAGE_DIR` | 留空自动查找；也可填写 `D:\DeepSeek Harness` 这样的客户端安装目录或客户端可执行文件路径 |
| `DSH_MODEL` | 聊天与任务模型，默认 `deepseek-v4-flash` |
| `DEEPSEEK_API_KEY` | DSH 使用的官方 API 凭据 |
| `LLM_PROVIDER` 及对应模型配置 | 辅助处理所用服务商及模型，不改变 DSH 主聊天模型 |

客户端版本不匹配会明确报错，不自动升级、降级或改用其他安装。机器人启动前检查安装和密钥；更新代码或运行参数后重启机器人及后台。模型支持的图像能力以所选模型为准。

验证时检查普通聊天、同一问题的追问、能力查询、获准的插件启停与任务状态查询。只发图片或拍一拍不应附加空文字。后台“提示词管理”可用人设对比试聊验证措辞与分条，规则及场景见 [人设](PROFILES.md)。

自动回归使用 `python -m unittest discover -s tests -q`，覆盖权限、空回复、分条、图片准备、回合取消、工具结果传递和试聊无写入。实际 QQ 收发与模型语气仍需在部署后观察；模型输出存在随机性。
