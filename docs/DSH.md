# DSH 聊天执行

## 设计

聊天由 DSH 主导回答与工具调用，根据本次会话中真实可用的能力完成检索、任务查询、插件操作与表达。机器人负责身份、权限、状态、发送事务和持久记忆，模型的成功描述不能代替执行结果。后台任务继续使用审批、排队和结果验证流程。

主执行会话按机器人账号、群或私聊对象持续保存，跨轮保留工具结果及未完成工作的上下文。草稿与平台已发送消息分开理解；发送成功、失败及过期状态作为模块事件提供。每轮重新核验身份与工具权限，清除历史或权限范围变化后建立新的执行上下文。聊天只开放已注册业务工具，不提供任意本机命令或文件操作。

程序负责唤醒频率、资源上限与执行边界；唤醒后由主 agent 决定回应、静默、查询、复读或执行任务。积极性影响唤醒频率与参与意愿，不再用相关性分数二次否决。新消息阻止过期副作用和发送，但不强制丢弃已完成的读取或取消后台任务。

客户端浏览记录按机器人账号、群或私聊对象汇总为连续会话，保留正常完成的模型回合及工具结果。浏览记录不作为机器人后续请求的历史来源；生成结果不代表平台发送成功。后台试聊不写入客户端会话。

自然表达遵循当前人设和上下文，减少机械开场、强行追问和重复总结。分条围绕完整意思，保护代码与列表，不调整既有发送停顿。后台的人设试聊使用虚构输入，无真实聊天副作用。

## 开发

- `plugins/tasks/desktop.py` 从 Windows 安装信息与常见安装路径定位客户端，读取 ASAR 元数据，校验客户端及随附 Harness 均为 `0.2.1-rc.2`。通过客户端 Electron 的 Node 模式执行随附 CLI，不调用全局 npm 包、不修改个人安装。
- `plugins/assistant/dsh.py` 的 `Chat` 在每次回复创建 `Turn`，使用临时启动配置及按机器人/会话隔离的持久 DSH 目录 `data/agent/<bot>/<scope>/<generation>`。同一会话串行恢复，调用原生 `agents.create/resume` 及 `sessions.flush`；代际由权限范围和清除历史标记决定。`ContextVar` 隔离并发回合；超时、取消和结束后关闭自己的进程树并清理临时目录。
- `dsh_bridge.mjs` 通过 Cordis 注册本轮业务工具，关闭全局工具及子代理入口，使用 DSH 原生工具循环。首轮将已组装上下文标注历史角色与当前请求后交给 DSH；之后只回传新工具结果，避免重复执行。图片先由 Python 按下载限制验证，再交给附件服务。
- Python 与桥接进程按 `call_id` 交换整批工具调用及对应结果。`LLM.investigate` 委托 `tools.py` 的注册表执行；独立只读调用并行，写操作构成顺序屏障。参数、作用域、审批、图片哈希和发送去重由原模块校验；原图在对应工具结果之后附加。查看图片不强制保存描述，不再封锁其他工具。
- `budget.py` 维护单次唤醒共享的工具次数、时间、Token 和可选费用预算，每次工具结果反馈剩余资源。默认 24 次工具调用、120000 Token，仍受完整请求超时约束。费用根据维护者配置的每百万 Token 单价保守估算，缓存输入按普通输入计价；0 表示不启用费用预算。Token/费用在模型报告用量后更新，阻止后续步骤，单次已发出的模型请求可能跨过阈值；不能视为服务商账单硬限额。
- `response.py` 的 `set_response` 接收回应/静默/复读、引用与话题状态。复读发送仍校验当前候选、冷却及实际发送去重；引用只接受已知消息。`events.py` 按机器人和会话保存最近 32 项模块状态，自动注入主回合；`Store.save` 产生任务状态事件，插件切换及发送结果在各自执行入口写入。任务终态通知由同一 `Chat` 主 agent 处理，可静默；后台事件不挂载需要新用户授权的任务修改或插件执行工具。审批请求仍走原有主人确认流程。
- `dsh_view.mjs` 使用客户端原生 JSONL/Zstd 持久化接口追加浏览记录。会话标识按机器人账号及正负会话范围区分；每次持有原生跨进程写锁，重新读取已有记录并续接回合编号，完整校验生命周期后整批写入。记录先原子写入客户端目录内的 `qqbot-pending` 队列，依据记录标识去重；客户端占用写锁时保留队列，机器人独立工作循环每 15 秒尝试补写，跨重启保留，重复补写不重复展示。展示保留用户输入、图片、模型消息及原生工具事件，不复制系统提示词和历史上下文。执行会话持久保存且与浏览镜像隔离；展示所需图片使用客户端的持久附件目录。保存失败仅记录 `dsh_view_save_failed`，不把客户端异常正文写入日志。
- `modules.py` 汇总任务和插件能力，插件启停复用现有鉴权入口；历史、表情、分享等仍使用各模块现有执行器。`chat.modules` 提示查询真实状态并区分待审批、排队、成功和失败。
- 认知提取、安全审核与后台修改建议继续使用辅助模型 API；参与决策和任务通知使用主 DSH agent。正式聊天无 API 直连回退分支。
- 诊断标准输出与标准错误不直接进入日志；结构化聊天上下文、回复及用量沿用现有诊断开关与脱敏机制。

## 使用说明

安装 Windows DeepSeek Harness 客户端 **0.2.1-rc.2**。配置 `.env`：

| 配置 | 含义 |
| --- | --- |
| `DSH_PACKAGE_DIR` | 留空自动查找；也可填写 `D:\DeepSeek Harness` 这样的客户端安装目录或客户端可执行文件路径 |
| `DSH_MODEL` | 聊天与任务模型，默认 `deepseek-v4-flash` |
| `DSH_VIEW_HOME` | 客户端数据目录；留空依次使用进程的 `DSH_HOME` 或当前用户 `~/.dsh` |
| `AGENT_MAX_CALLS` / `AGENT_MAX_TOKENS` | 每次唤醒共享工具次数与 Token 预算 |
| `AGENT_MAX_COST` | 可选费用上限，默认 0；需配输入与输出单价 |
| `AGENT_INPUT_PRICE` / `AGENT_OUTPUT_PRICE` | 每百万 Token 单价，币种需与费用上限一致；不自动获取价格 |
| `DEEPSEEK_API_KEY` | DSH 使用的官方 API 凭据 |
| `LLM_PROVIDER` 及对应模型配置 | 辅助处理所用服务商及模型，不改变 DSH 主聊天模型 |

客户端版本不匹配会明确报错，不自动升级、降级或改用其他安装。机器人启动前检查安装和密钥；更新代码或运行参数后重启机器人及后台。模型支持的图像能力以所选模型为准。

验证时检查普通聊天、同一问题的追问、能力查询、获准的插件启停与任务状态查询。只发图片或拍一拍不应附加空文字。后台“提示词管理”可用人设对比试聊验证措辞与分条，规则及场景见 [人设](PROFILES.md)。

自动回归使用 `python -m unittest discover -s tests -q`，覆盖权限、空回复、分条、图片准备、回合取消、工具结果传递和试聊无写入。实际 QQ 收发与模型语气仍需在部署后观察；模型输出存在随机性。

### 在客户端查看

重启机器人后，正常完成的新聊天回合会追加到客户端数据目录的 `sessions` 中，归属本项目工作目录。在 DSH 客户端的会话列表中查找“群名（群号）”或“昵称（QQ号）”。名称从平台联系人缓存读取，缺失时使用历史消息的平台名称，再缺失则显示“群名待同步”或“昵称待同步”；已有会话在下次正常完成的回复追加时更新标题。标题不改变内部机器人账号隔离。同群不同发送者进入同一会话，每次提问标明发送者和请求编号；不同机器人账号、不同群和不同私聊彼此隔离。列表未刷新时重新打开会话列表，必要时重启 DSH 客户端。客户端若持有当前会话写锁，新记录会暂存在待同步队列；关闭或离开该会话释放写锁后，机器人会自动补写，再打开即可查看。

展示在模型完成后追加，不是实时流式镜像。保留输入图片、工具调用/结果和模型生成内容；失败或取消回合不追加。此处显示的是生成记录，平台发送结果仍以 QQ 和机器人档案为准。在 DSH 客户端继续聊天不会向 QQ 发送消息，客户端续聊产生的内容也不会回灌机器人上下文。

默认本机目录为 `%USERPROFILE%\.dsh`；若客户端使用自定义数据目录，在后台“设置 → 聊天与任务执行”填写相同目录，或配置 `DSH_VIEW_HOME` 后重启机器人。目录应填写数据根目录，而非 `sessions` 子目录或客户端安装目录。

此功能只记录启用后的新回合，不回填此前已清理的临时执行记录；后台人设试聊、辅助模型操作及自主任务的独立运行日志不进入这些聊天会话。记录保存在 DSH 数据目录，连同待同步队列独立于机器人私有迁移包和日志保留天数；迁移或清理时应通过 DSH 单独管理。

执行快照 `data/agent` 是本机 DSH 运行状态缓存，不纳入机器人迁移包；换机从已迁移的真实聊天、任务台账和模块事件重新建立执行会话。客户端浏览镜像仍由 DSH 单独管理。`data/agent-events` 随私有包迁移，按事件编号合并且保持账号隔离。自动测试见 `tests/test_agent.py`；`python -m tests.smoke_agent` 使用真实 API 验证原生恢复与多工具调用，不发送 QQ 消息。
