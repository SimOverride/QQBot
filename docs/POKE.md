# 拍一拍

## 设计

机器人能得知谁拍了自己，并按当前人设和会话气氛决定文字回应、拍回去或保持安静。群聊和获准私聊均支持。机器人也可根据明确请求或轻量聊天互动拍别人；群聊只拍当前群成员，私聊只拍当前聊天对象，不拍机器人自己。

具体如何应声、什么时候拍回、连续被拍时如何收住，以及主动拍人的偏好，直接写在各份人设中。公共功能提示词只描述调用方法和程序约束，不编排角色反应。

平台通知是发生过的互动，不是用户发言，不提供额外操作授权，也不作为个人长期认知的自述依据。机器人自己的动作通知不触发新回复，其他人被拍也不触发本功能。通知只有本地事件编号，不能作为 QQ 消息引用目标。

同一人的短时连续通知记录进当前会话，运行期间十秒内只触发一次处理。发送每轮最多尝试一次，运行期间同一会话同一目标三十秒内最多一次。发送结果不明时不重试，不声称成功；发送状态记录失败时不发送。可只拍一拍而不附带文字。

## 开发

- `plugins/assistant/__init__.py` 通过 `on_notice` 接收 OneBot `PokeNotifyEvent`。`poke.py` 校验机器人账号和 `target_id`，群聊以 `user_id` 为拍人者，私聊优先使用 NapCat 的 `sender_id`，避免把会话对象误当作实际发送者。只接收别人拍当前机器人的通知。
- `Pokes.dispatch` 对私聊沿用好友、共同群或机器人主人资格检查，通过后记录通知并调用现有群聊或私聊流程。群聊作为直接互动进入短时合并，由参与模型决定是否回应；被拍沿用直接互动入口，跳过普通话题参与门槛。模型拒绝参与或决定安静时不发送额外提示。
- 通知以 `poke` 类型写入 `messages`，元数据保留拍人者和目标。编号由机器人、会话、发送者、目标和事件时间的指纹生成，使用低于常见 QQ 消息编号的负数范围，重复上报和重启后同一通知不会再次触发。没有独立新增数据库表。`longterm.py` 在历史查询和群上下文返回事件资料，但自动认知提取跳过 `poke` 类型，并正常推进游标。
- `HistoryTools.poke` 为本次请求绑定 `PokeSession`。`llm.py` 只在回复阶段提供 `poke_user`，参与判断不提供发送工具。群目标通过实时 `get_group_member_info` 核实；私聊只接受当前对象的 QQ，不允许模型指定另一个会话。
- 实际发送调用 NapCat `send_poke`；群聊传 `group_id` 和 `user_id`，私聊只传 `user_id`。接口定义见 [NapCat API](https://napcat.apifox.cn/250286923e0)，通知字段见 [NapCat 通知实现](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/event/notice/OB11PokeEvent.ts)。
- 发送前在原消息的元数据写入 `poke_action`，包含目标和 `attempting` 状态；随后更新为 `sent` 或 `send_unknown`。同一原消息重新进入流程也不能再次发送。成员查询后再次检查消息是否过期，过期回复不执行拍一拍。平台请求等待上限八秒，异常和超时均不自动重试。
- `Reply.poke_target` 仅包含平台已确认的成功目标，`service.py` 可在没有文字回复时保存成功动作说明。只有被拍通知或成功动作允许空文字结果；普通请求空回复仍是错误。通知编号在 `groupchat.py` 的引用校验中排除。
- `personas/*.txt` 的“拍一拍互动”章节维护具体角色反应，同时传入回复和参与判断。`prompts/catalog.json` 的 `llm.poke.0`、`llm.poke_plan.0` 和 `tool.poke_user.description` 仅维护调用参数、通知字段、处理结果和程序限制，沿用后台提示词覆盖。

## 使用说明

更新后重启机器人即可，无需新增密钥或配置。群聊或获准私聊中双击机器人头像进行拍一拍；机器人根据人设和聊天气氛回应，并非每次都固定拍回去。

之后仅编辑人设或公共提示词正文时，下次请求实时读取，无需重启。具体反应在提示词管理的人设中修改，公共“拍一拍调用说明”和“拍一拍通知字段与处理结果”只用于维护调用约定；本机已保存的覆盖优先于代码默认值。

群内可说“@机器人 拍一下 @某人”或“拍一下某某”，私聊可说“拍我一下”。目标昵称重名时应明确指定 QQ 或平台 @。未 @ 的群消息沿用普通参与判断，机器人决定参与后也可使用拍一拍工具。

验证步骤：

1. 在群里拍机器人，确认它能识别拍人者，可回复或拍回去，回复不引用本地通知编号。
2. 在私聊拍机器人，确认回应仍在该私聊，机器人自己的拍回通知不会再次触发。
3. 请求拍当前群成员，检查实际拍一拍动作；请求拍当前群外的人或在私聊拍第三者应被拒绝。
4. 连续拍机器人或连续要求拍同一人，检查去重和冷却，不形成循环。
5. 平台发送失败或连接中断时，检查机器人没有声称成功，也没有重复发送。

若完全收不到被拍通知，检查 NapCat 与机器人的 OneBot 事件连接。若能回应但无法拍回，检查 NapCat 的 `send_poke` 支持和平台后端状态；部分 QQ 或 NapCat 版本需要配置可用的 packetBackend。详情见 [NapCat 高级配置](https://napneko.github.io/config/advanced)。

自动回归：`.venv\Scripts\python.exe -m unittest discover -s tests -p test_poke.py`。测试使用实际通知模型、模拟平台和隔离数据库，覆盖群聊、私聊、两家模型协议、纯动作回复、静默、去重、冷却、过期请求、目标校验和失败状态。测试不会操作真实 QQ；实际拍一拍仍需在当前 NapCat 与 QQ 客户端中验证。
