# 私有数据迁移

## 设计

迁移工具把机器人全部有效私有数据保存为不加密 ZIP，供同一机器人 QQ 在机器之间迁移。只允许同号合并，不支持跨机器人账号转移。新部署没有账号证据时，由操作者明确指定目标 QQ；该声明不是 QQ 登录验证。

范围包括聊天档案、完整问答、长期认知、认知处理进度、隐私审核及发送记录、表情图片和内容记忆、群设定、全部本地人格与风格，以及包含密钥的运行配置。不包含运行日志、代码、虚拟环境和外部 QQ/NapCat 登录态。

重复消息保留目标已有内容；独有数据并入。认知冲突采用更新时间较新的记录，同时间保留目标；隐私审核冲突采用不公开结果。配置冲突目标优先，补齐来源缺项。删除记录没有跨机器删除标记，因此合并旧备份可能恢复另一侧已经删除的数据。

导出允许机器人运行，数据库采用包含已提交 WAL 数据的快照。多个数据库、配置和图片不是同一时刻的全局快照；严格一致的迁移应先停止机器人。导入必须离线，导入前自动备份，失败恢复原数据；导入不会发送 QQ 消息。

## 开发

入口为根目录 `migration.py`，沿用现有 Python 和 python-dotenv，无新增依赖。

- `export`：读取 `data/memory.sqlite3` 和 `data/identity.json` 确定唯一账号；使用 SQLite backup 导出数据库，生成含文件大小和 SHA-256 的 `manifest.json`。ZIP 统一将图库放在 `emotes/`。
- `import`：校验 ZIP 路径、文件清单、大小、哈希、账号及数据库结构，然后在临时目录合并。当前仅接受本版本已知结构，不执行来源触发器。默认解压限制为 20 GiB、50000 个文件。
- 消息按 `(bot, grp, message_id)` 去重，重新分配内部主键并映射认知、审核和分享记录的 `source_id`。已处理消息排在待处理消息前，重建每个用户的认知游标；双方任意一侧已处理的重复消息不重复提取。消息原始时间不变，内部 ID 顺序不保证全局时间顺序。
- 完整问答按消息键去重；表情描述按内容哈希和更新时间合并。已有发送尝试记录继续保留，以避免重复发送；指向已不存在消息的审核/分享记录不迁移，失去依据的认知来源改为空。
- `.env` 按键保留目标值并补齐缺项；图库路径采用目标机器的项目内目录，默认 `emotes`。不支持项目外图库或目录链接。已有项目中同名不同内容的人格、风格和图片保留两份，来源文件增加内容哈希后缀，并调整来源群配置的人格/风格选择。新部署则直接恢复来源文件。
- `backups/` 保留导入前 ZIP、来源 ZIP 和精确回滚副本。先写 `data/migration-pending.json`，再发布文件；异常自动回滚，进程崩溃后用 `recover` 恢复。恢复完成才移除日志。
- `bot.py` 和导入工具共享 `data/.runtime.lock`；存在未恢复事务时禁止启动。导出、导入另用迁移锁互斥。Windows 同时检测未升级的旧机器人进程。其他平台的旧版机器人必须由维护者先停止。

导入账号检查依据本地数据及新部署的显式目标参数。它不验证之后 NapCat 实际登录的账号，启动前需自行核对。

## 使用说明

在项目根目录执行：

```powershell
# 导出当前全部数据，自动生成 backups 下的 ZIP。
.\.venv\Scripts\python.exe migration.py export

# 同号已有数据：停止目标机器人后合并。
.\.venv\Scripts\python.exe migration.py import "D:\备份\qqbot.zip"

# 新机器：先从 GitHub 下载同版本代码并安装依赖，再明确指定目标机器人 QQ。
.\.venv\Scripts\python.exe migration.py import "D:\备份\qqbot.zip" --bot-qq 1625123422

# 导入意外中断：停止机器人后撤销未完成事务。
.\.venv\Scripts\python.exe migration.py recover
```

可用 `export --output "完整ZIP路径"` 自定输出位置，已有文件不会覆盖。默认备份目录被 Git 忽略；包内含明文密钥及聊天记录，不要提交或公开分享。

新部署可以不预先创建 `.env`，这样直接恢复来源配置；若已有 `.env`，已有值优先，包括空值。QQ/NapCat 需在新机器单独安装并登录同一账号，OneBot 客户端 Token 必须与最终 `.env` 一致。

导入成功后启动机器人，检查连接日志，在 QQ 发送 `/ping` 和 `/记忆` 验证。出现账号不一致时核对目标账号，不能修改备份清单绕过检查。数据库结构不兼容时先对齐两边代码版本。路径/哈希错误应重新导出。未完成导入时不要手动删除恢复日志，先执行 `recover`。

自动测试覆盖 WAL 快照、新部署恢复、同号重复合并、来源引用映射、游标待处理保留、异号拒绝、路径穿越和篡改拒绝、配置冲突、表情记忆合并、运行锁及失败恢复。
