# 表情收藏与使用

## 设计

机器人按统一人设、兴趣、话题及实际原图决定收藏、描述和发送。查看与收藏、发送相互独立；收藏或发送网络图片时仍需独立内容审核。图库中的视觉描述与使用反馈进入同一机器人的统一记忆库，不按群保存不同认知。

视觉描述说明画面、文字、情绪和适用场景。反馈说明实际发送的语境、反馈者和反响，主观看法不能改写图片的客观内容。相同图片按内容摘要关联；个人偏好按 QQ 区分并跨群聊、私聊使用，一个人的不喜欢不会成为其他人的禁用。不同机器人账号不共享反馈。

表情反馈由模型结合上下文判断并显式调用工具。程序不通过关键词、标点、时间窗口、发送唯一性或反馈者身份预判是否允许记忆。可引用多条跨会话消息，也可记录明确标注的模型主观看法。成功发送账本仅为模型提供参考；发送失败不生成成功账本。

模型通过停用或恢复工具修改全局或指定用户的使用状态。程序执行该状态，但不判断聊天是否命中特定拒绝措辞。经验更新保留历史并检查版本；引用的来源失效时停止使用对应经验。人工编辑不锁定后续模型修正。

## 开发

- `plugins/assistant/emotes.py` 管理已核验的本地图片、成功使用次数及统一库访问。视觉描述是 `emote` 类型笔记，字段按图片摘要独立；已有 SQLite 描述仅作为首次使用时的迁移来源，一旦统一笔记存在便以其为准。旧描述保留人工来源标记，后续允许模型修正。真实机器人新收藏及查看记忆直接写入统一库。
- `plugins/assistant/emote_feedback.py` 保存 `emote_sends` 成功发送账本，绑定机器人、会话、平台消息编号、目标用户及发送语境。读取反馈工具可同时查看账本，写入不强制绑定某次发送。
- 不再在后台整理消息时自动运行反馈正则。`save_feedback` 保存工具给出的主体、好恶、使用建议和来源；无来源时使用 `authored=model` 标明模型主观经验，不伪造聊天证据。
- `plugins/assistant/emote_state.py` 提供 `manage_emote_memory`，先读取版本，再调用 `remember`、`disable` 或 `enable`。`subject=0` 表示全局，否则为人物 QQ；`message_ids` 使用同账号消息内部编号，可多条、跨群、跨用户或为空，非空编号必须存在。`sentiment` 为 positive/negative/uncertain，由模型给出。旧群经验由整理器首次处理该账号时幂等转入待审笔记，保留原群、停用及历史，不虚构发送绑定或自动扩大停用范围。
- `list_emotes` 返回图片描述和相关经验，以当前用户的明确正负反馈调整排序，过滤对其停用的图片；其他用户的意见作为有主体标记的参考。选择与实际发送前再次检查有效禁用，避免旧候选绕过更新。
- `emote_collect.py` 分离下载查看和独立审核；候选按机器人/会话缓存在 `data/emote-candidates`，可在后续回合重开。该临时缓存不迁移，失效链接需重新搜索。
- 图片下载继续经过公网地址、重定向、大小和格式校验；收藏及发送受整轮预算和图库容量约束。统一笔记随记忆库迁移，成功发送及使用账本随图库数据库迁移。

## 使用说明

后台表情详情可查看统一描述与相关反馈，通过记忆库维护认知或归档错误经验。人工修改按后台差异确认与版本核验保存。不要直接修改图库数据库中的旧描述来更改当前记忆。

需要反馈具体图片时，回复机器人实际发送的图片最可靠，例如“这张图很贴切”“以后别给我发这张图”“这张图可以再发了”。不回复图片时也可由主模型理解上下文并调用工具，不要求固定句式或反馈时间窗口。建议明确指向哪张图片，方便模型判断。

工具调用才会更新经验；模型可以根据对话判断全局或个人范围。正面经验影响推荐排序，不保证每次发送同一张图。实际消息来源删除会使依赖它的经验失效。

验证使用隔离虚构图片和平台消息：`python -m unittest tests.test_emote_feedback tests.test_agent_memory tests.test_emote_collect -q`。覆盖跨会话偏好、不同账号隔离、多来源及无来源工具调用、停用恢复、修正历史、来源失效、人工内容可更新及推荐排序。真实 QQ 收发与模型对复杂语境的判断需部署后观察。
