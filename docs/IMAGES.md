# 表情收藏与使用

## 设计

主 agent 按人设、话题及实际原图自主决定收藏、描述、发送和后续修正。查看原图不触发审核；收藏或发送网络图片时独立进行隐私及内容审核。审核不判断审美与收藏价值，收藏描述由主 agent 根据原图填写。

收藏与发言独立，静默观察时仍可收藏。取消每轮候选、下载尝试、审核次数和收藏张数的小额限制；处理仍受整轮工具、Token、时间预算、图片大小及图库容量约束。可依次选择多张图片，后选不覆盖先选；发送前逐张校验状态，成功才计入使用记录。

原图客观描述公共复用，各群的使用经验按机器人账号和群号隔离。经验可以记录发送时机、群友实际反馈及不确定性，并由 agent 后续修正。没有回应不表示不喜欢，相邻消息不一定是在评价图片。

agent 只能按群停用图片，必须说明原因并提供本群真实反馈依据；不提供删除或跨群停用能力，也不能自行恢复停用。停用不删除文件，不影响其他群。后台可查看状态、原因和依据并手动恢复。

## 开发

- `emote_collect.py` 分离下载查看与独立审核；收藏时接收主 agent 的描述。网络候选使用来源摘要生成稳定编号，按机器人/会话缓存在 `data/emote-candidates`，后续回合可重新查看。该缓存不迁移；临时地址失效时重新搜索。
- 历史群图经 `view_image` 从当前群留档读取后，可重新加入收藏候选；私聊图片不能因此进入群收藏候选。图片读取、下载和审核仍校验来源、格式、大小、公网地址和重定向。
- `tools.py` 将 `choose_emote` / `choose_image` 选择加入有序发送队列；`service.py` 逐项发送和记录。查看图片不要求先记忆描述。已有客观描述修正仍提交后台建议，不覆盖维护者原值。
- `emote_state.py` 提供 `manage_emote_memory`：读取本群状态、记录或修正使用经验、停用。写入需提交读取版本、原因或经验及平台消息编号，执行器校验反馈来自本机器人当前群且不是机器人自己的消息。
- 图库数据库 `emote_group_state` 按机器人、会话和图片摘要保存停用标志、原因、使用经验、反馈快照、更新时间和旧版本。检索排除本群停用图，工具选择与发送前再次校验，避免旧会话候选绕过限制。
- 后台表情详情返回 `group_states`；恢复接口 `/api/emotes/restore` 使用本机页面令牌和版本核验。状态及历史随图库数据库迁移，按复合主键合并，保留较新版本。
- 下载继续使用 `image_download.py` 的公网地址与文件校验；Fake-IP 使用既有受控 DNS 解析，不能通过模型提供的内网地址绕过校验。

## 使用说明

重启机器人与后台。后台“表情包管理”选择图片，在“各群使用情况”查看机器人账号、群号、停用状态、原因、使用经验及反馈记录。点击“恢复本群使用”仅恢复所选群；版本冲突时刷新后操作。

配置搜索服务后可搜索图片，关闭自动收藏仍允许搜索配图。日收藏额度和图库容量仍是存储管理限制；每轮两张收藏、单张发送等限制已取消。辅助审核不通过时不能发送或收藏，但不妨碍主 agent 查看图片和回应内容。

验证：同一图片在一个群停用后，该群不能检索或发送，其他群仍可使用；旧选图结果在发送前也应被拦住。记录群友反馈后查看经验，重复提交旧版本应冲突。多图按选择顺序发送；失败不得算作成功使用。自动验证见 `tests/test_agent_memory.py`、`tests/test_emote_collect.py` 和 `tests/test_image_send.py`。
