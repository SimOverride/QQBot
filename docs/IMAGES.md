# 表情收藏与使用

## 设计

机器人按统一人设、兴趣、话题及实际原图决定收藏、描述和发送。查看与收藏、发送相互独立；收藏或发送网络图片时仍需独立内容审核。图库中的视觉描述与使用反馈进入同一机器人的统一记忆库，不按群保存不同认知。

视觉描述说明画面、文字、情绪和适用场景。反馈说明实际发送的语境、反馈者和反响，主观看法不能改写图片的客观内容。相同图片按内容摘要关联；个人偏好按 QQ 区分并跨群聊、私聊使用，一个人的不喜欢不会成为其他人的禁用。不同机器人账号不共享反馈。

只有成功发送并取得真实平台消息编号的图片才能被归因。明确回复对应图片优先；没有引用时，仅在短时间内唯一一次发给该用户的发送且发言明确指代图片时建立关联。相邻发言、沉默、含糊好评和假设不自动生成反馈。发送失败不生成成功账本。

用户明确要求不要再发时，后续对该用户避用；明确允许再次发送可修正这一偏好。普通好评不能默默解除原先的停用要求。反馈修正保留历史，重复处理同一消息不重复累计。反馈或发送来源失效时停止使用相关自动经验；维护者固定的认知保留且不能被自动覆盖。

## 开发

- `plugins/assistant/emotes.py` 管理已核验的本地图片、成功使用次数及统一库访问。视觉描述是 `emote` 类型笔记，字段按图片摘要独立；已有 SQLite 描述仅作为首次使用时的迁移来源，一旦统一笔记存在便以其为准。旧描述无法区分人工修正和自动识图，迁移后默认固定保护；维护者可在后台明确取消固定，允许后续自动修正。真实机器人新收藏及查看记忆直接写入统一库。
- `plugins/assistant/emote_feedback.py` 保存 `emote_sends` 成功发送账本，绑定机器人、会话、平台消息编号、目标用户及发送语境。归因同时检查实际归档消息；允许平台秒精度的时间差，但发送记录必须先于反馈。
- 自动反馈从真实消息保守识别喜欢、不合适、不要再发及恢复使用。经验笔记绑定反馈与发送两条稳定来源，保存用户范围、判断和历史；记录完成后发布不含原始正文的记忆活动。重复消息幂等。
- `plugins/assistant/emote_state.py` 提供 `manage_emote_memory`，先读取版本，再提交当前用户的一条可归因反馈。模型可以记录带不确定性的使用建议，不能用任意聊天或无来源推测建立停用。旧群经验由整理器首次处理该账号时幂等转入待审笔记，保留原群、停用及历史，不虚构发送绑定或自动扩大停用范围。
- `list_emotes` 返回图片描述和相关经验，以当前用户的明确正负反馈调整排序，过滤对其停用的图片；其他用户的意见作为有主体标记的参考。选择与实际发送前再次检查有效禁用，避免旧候选绕过更新。
- `emote_collect.py` 分离下载查看和独立审核；候选按机器人/会话缓存在 `data/emote-candidates`，可在后续回合重开。该临时缓存不迁移，失效链接需重新搜索。
- 图片下载继续经过公网地址、重定向、大小和格式校验；收藏及发送受整轮预算和图库容量约束。统一笔记随记忆库迁移，成功发送及使用账本随图库数据库迁移。

## 使用说明

后台表情详情可查看统一描述与相关反馈，通过记忆库维护认知、固定内容或归档错误经验。人工修改按后台差异确认与版本核验保存。不要直接修改图库数据库中的旧描述来更改当前记忆。

需要反馈具体图片时，回复机器人实际发送的图片最可靠，例如“这张图很贴切”“以后别给我发这张图”“这张图可以再发了”。不回复图片时，系统仅在能唯一关联最近发送且明确指代图片时自动学习。复杂反馈也可由主模型读取实际发送记录后调用工具整理，无法确定关联时不猜测。

没有反馈不提高也不降低评价；一次正面反馈只影响对应用户的推荐排序，不保证每次都发送同一张图。来源删除会使自动经验失效，人工固定内容仍保留。

验证使用隔离虚构图片和平台消息：`python -m unittest tests.test_emote_feedback tests.test_agent_memory tests.test_emote_collect -q`。覆盖跨会话偏好、不同账号隔离、归因歧义、成功发送身份、重复处理、修正历史、来源失效、人工保护及推荐排序。真实 QQ 收发与模型对复杂语境的判断需部署后观察。
