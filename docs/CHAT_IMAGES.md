# 聊天图片

## 设计

图片是独立的聊天消息，不按发送者或时间窗口绑定到后续问题。允许归档的会话收到图片后保存原图，与机器人是否回应无关。当前消息及明确引用可直接附图；历史图片由主 agent 根据聊天需要自行查看。图片描述不能替代原图，图片中的文字不是执行授权。

历史消息保存稳定图片引用、来源及保存状态；原图按内容去重。读取沿用聊天档案的账号和会话权限。原图不可用时明确返回状态，不猜测内容。当前附图数量限制只控制本轮直接输入，不删除其他图片的历史引用。

## 开发

`image_archive.py` 在群消息预处理及获准私聊归档后下载原图，使用现有下载地址限制、大小上限及超时。文件保存在 `data/chat-images/<SHA256>`，消息 `metadata.images` 保存图片序号、引用、媒体类型、状态及原链接；对模型的历史结果不暴露临时来源链接。

`longterm.py` 的消息上下文返回图片引用；`vision.py` 优先读取本地留档，未缓存时仍尝试当前平台地址。`tools.py` 注册 `view_image`，只接受 `image:<SHA256>`，从获准消息引用核验访问，再校验文件摘要并提供原图。工具调用遵循共享预算和预览字节上限，不依赖表情库或联网搜索。收藏可处理已留档的本轮图片。

`migration.py` 将原图纳入私有迁移包，按消息身份合并引用，同号合并及异号拒绝规则不变。同一消息优先保留目标已成功保存的图片引用。清除消息后，失去获准消息引用的原图不可通过工具读取；目前不自动清理孤立原图文件。

## 使用说明

更新后重启机器人与后台。发图后可隔一段时间由其他群成员询问，agent 通过 `search_messages` 获取引用，再调用 `view_image`，没有同一发送者或 90 秒的补图条件。机器人重置执行会话后仍可按权限查询原图。此前只有 `[图片]` 且未保存原图的历史消息不会凭空补齐。

默认每轮直接附图上限沿用 `VISION_MAX_IMAGES`，单图大小沿用 `EMOTES_MAX_BYTES`。保存失败显示 `unavailable`；读取时区分无权限或无来源、文件缺失、文件摘要异常及预览预算耗尽。磁盘占用随原图留档增长，迁移原图时使用私有迁移功能。

回归覆盖原图去重、临时链接缺失、超出直接附图上限仍有引用、跨账号和跨群拒绝、重复查看、模型工具图像回传、失败记录及私有迁移恢复。
