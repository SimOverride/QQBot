# 统一记忆与认知

## 设计

同一机器人账号在所有群聊和私聊中共享记忆、人物认知与人设。人物使用 QQ 标识，昵称只用于显示；群号、私聊和发送时间记录信息来源，不划分认知空间。不同机器人账号保持隔离。读取记忆不扩大发送消息、执行任务或管理插件的权限。

长期内容分为事实、事件、主观印象、群背景、自我档案、想法、日记、表情经验及导航索引。事实只能由真实用户消息提供依据；主观印象与自我记录不当作事实或程序权限。没有把握的日期保留 unknown。修正保留旧内容及依据，不能静默覆盖历史。

人工固定内容，包括空值，不受自动整理覆盖。存在冲突的旧人工内容进入隔离，等待维护者处理。自动内容的来源删除或正文修改后停止召回；人工固定内容独立保留。修改需检查版本，读取和整理不能自行强化记忆。

遗忘体现为召回权重下降，不删除原文。自动内容采用30天半衰期，权重低于0.1不进入自动召回；人工固定和自我档案不衰减。有新的真实证据才能强化，强化间隔至少24小时。日记每天最多由聊天工具保存三次。

日常管理按人物、主题、事件、群背景、机器人和表情阅读完整视图。空白保护记录和内部索引不占普通列表；相同正文合并展示，原始证据仍独立保留。归并不将不同事实强行融合，也不自动判断同义内容完全等价。

机器人自身兴趣在所有群聊与私聊统一。群管理只维护参与与功能设置，群背景作为共享记忆保留来源。表情的实际反馈属于发言人，不能把一个人的偏好推广给其他人。

## 开发

### 存储和来源

`plugins/assistant/vault.py` 管理 `data/memory-vault/<机器人QQ>/<记忆编号>.md`。Markdown 正文是唯一有效正文，YAML 元数据包含类型、人物、字段、固定状态、历史版本和稳定来源。来源由机器人、会话、发送者、平台消息编号、时间和正文指纹组成，不依赖数据库自增主键。版本由文件内容计算，写入使用项目锁、乐观并发和同目录原子替换。

`data/memory.sqlite3` 保留原始消息、问答和发送去重账本。旧 facts 与整理缓存仅由离线升级程序解释；运行时不再向旧认知表或缓存写入。`consolidation.py` 服务于旧资料迁移，不能作为新记忆写入入口。

### 整理生命周期

`memory_worker.py` 在采集真实用户文本时写入 `data/memory-jobs/<机器人QQ>/`，机器人进程运行期间串行处理待办。它不依赖一轮 DSH 子进程存活，静默收到的文本也可以整理；重启后恢复未完成任务。

整理调用当前配置的辅助模型，通过独立结构化输入传递当前发送者、当前原始文本、时间及候选事实。不会把拼装后的历史背景或助手答案当作当前用户证据。每次最多五项 ADD、UPDATE、CORRECT、REINFORCE；保存执行计划和逐项检查点，写入前复核来源、主体、固定状态、版本及幂等操作编号。失败按退避重试，状态只记录错误类型。事件日期与旧版本保留于笔记元数据。人物导航索引在事实处理后更新，并绑定依据笔记版本；来源被清除或笔记更新后，旧索引不能继续提供旧正文。完成结果区分实际保存、固定保护、版本过期、重复强化冷却和没有长期信息。

`Vault.overview()` 从有效非空笔记构建阅读视图，按正文规范化去重展示；不创建第二份事实库。`memory_records.py` 在有真实任务时从当前人设初始化机器人自我档案，后续自主或人工修改后不再被初始化覆盖。每日实际记忆变化生成有依据的记录；它不是虚构的经历或情绪，主模型仍可用工具维护独立想法和日记。

`memory_activity.py` 每个机器人保留最近200条活动，仅记录标识、结果、排除原因和调用耗时，不重复存储聊天正文。`processing_completed` 包含实际动作结果，`recall` 记录最终注入与排除项；注入不等于模型已经采纳。当前提供调用次数及耗时，不估算供应商账单。

`manage_memory` 用于主会话维护统一主观认知、群背景、自我档案、想法与日记，先 read 再 write；事实与事件由持久队列整理。历史读取可跨同一机器人全部会话，发送权限仍独立校验。后台模型只生成建议，经维护者查看差异并确认后保存。

### Basic Memory 接入

采用 [上游记忆设计](https://github.com/XRH66/codex-deepseek-starter/blob/main/docs/memory.md) 的 Markdown 库、回答前召回、后台整理、历史纠正、衰减和主观记录分层；针对 QQ 身份、后台固定值和短生命周期 DSH 进程，在本项目适配这些流程。记忆桥设计参考提交为 `8a8f832a1038cbb4595331aaf08ecb8d4c2a4842`。本项目没有加载上游网页人设插件，也不改动用户全局 DSH 配置。

`memory_index.py` 启动独立 Basic Memory 0.24.1 本机 stdio MCP。独立环境位于 `data/memory-engine`，每个机器人索引及配置位于 `data/memory-index/<QQ>`；索引目录不进入迁移包。引擎自动索引 Markdown，关闭自动升级、遥测和自动补写 frontmatter。依赖版本见 `requirements-memory.txt`。

当前使用 Basic Memory 文本检索，没有启用向量模型或外部 embedding 服务。启动预热与每次1.5秒的检索预算分离，失败降级到有效笔记的中文双字词检索。索引结果必须回读当前笔记并校验来源，不能直接引用过期索引摘要。保留事实、主观记录、索引与自我档案各通道上限，同时与跨会话近期片段共用2400字正文预算。近期片段最多600字，来自同一人物的真实发言与已发送机器人消息，明确标注历史角色，不转变为当前委托或持续授权。预算不是整个请求的Token上限。

Basic Memory 独立软件遵循 AGPL-3.0-or-later；上游记忆桥与整合项目为 MIT，许可证不能相互替代。Obsidian 打开同一个 Vault；后台生成中文导航及图谱页，并提供待审编辑工作台。派生图谱按共同人物建立连接，不推断未经证据支持的社会关系。工作台、导航和图谱由 `.gitignore` 与独立索引 `.bmignore` 排除，不作为记忆召回来源。受保护编辑使用工作台：原始版本基线放在库外，后台确认差异后才写正式笔记；直接修改根目录源笔记不能获得工作台的历史和冲突保护。

## 使用说明

1. 执行 `powershell -ExecutionPolicy Bypass -File scripts/setup_memory.ps1` 安装独立引擎。首次索引启动会预热；状态可在后台查看。
2. 已有旧认知的部署，先停止机器人，在后台数据迁移页面预演并执行统一记忆升级；也可运行 `python scripts/upgrade_memory.py` 预演，添加 `--apply` 发布。详见 [迁移](MIGRATION.md)。未升级时机器人拒绝启动，避免混用新旧认知。
3. 后台“记忆库”按人物、主题、事件、群背景或表情查看内容。展开证据后编辑、固定或归档；勾选维护记录才显示空白保护、隔离等内部记录。“机器人档案”查看自我档案、想法与实际记忆变化。
4. 在设置页选择全局人设及机器人兴趣；所有群聊和私聊共用。旧群兴趣读取时合并去重，机器人启动或保存设置时持久化统一配置；单纯读取已有配置不写文件。
5. “记忆活动”查看新增/修正、未保存原因、召回参考、冲突和调用耗时。记忆库的召回测试仅运行本地选择，不调用模型、不发送QQ消息。失败任务保留并重试；损坏任务旁的 `.error` 文件提示恢复备份。
6. `/忘记` 保存人工固定空值，不会因为旧消息再次被整理而恢复同字段内容。清空原消息会让依赖它的自动记忆失效；需要彻底销毁的资料还应考虑既有备份与笔记历史。

7. 在记忆库点击 Obsidian，刷新导航后打开本机库。选中笔记创建工作台稿件，在 Obsidian 编辑，回后台审阅差异并确认。正式笔记若已变化则拒绝覆盖；导航可重建，编辑稿不会被刷新覆盖。

验证使用独立虚构数据：`python -m unittest tests.test_vault tests.test_memory_upgrade tests.test_console_memory -q`。安装引擎后运行 `python -m tests.smoke_memory` 验证真实 MCP 索引、检索及原文不被改写，不调用实际模型、不读取正式聊天。模拟整理测试不代表实际模型语义提取准确率已验收。

首次使用 Obsidian 必须登记仓库：后台复制完整仓库目录，点击“首次接入：打开仓库管理器”，在 Obsidian 选择“打开文件夹作为仓库”并选择该目录。完成后回后台点击“刷新接入状态与待审稿”；之后可直接打开导航和编辑稿。安装软件、注册协议或生成导航都不等于登记仓库。后台只读检测客户端登记，不修改客户端全局配置。打开按钮通过已鉴权的本机后台调用系统启动 Obsidian，不依赖浏览器跳转外部协议；页面会显示请求结果，启动失败时提示检查安装。
