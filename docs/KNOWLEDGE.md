# Agent 认知与记忆

## 设计

主 agent 在消息触发的处理过程中，自主决定读取依据、新增认知、整理重复内容或修正旧判断。没有固定消息数量门槛、每日整理阶段或独立提取模型。无人发消息时不自主唤醒整理。

个人总体认知按机器人和用户归属，会话印象与群内分类按会话隔离；群摘要与群认知只属于对应机器人及群。仅记录有实际消息依据的信息，保留语境、时间条件及不确定性；没有新证据不因时间推移删除结论，矛盾不能擅自认定一方正确。

人工固定内容（含固定空值）不可被自动记忆覆盖。写入须检查读取版本、消息归属和来源有效性。图片中的文字、历史指令和昵称均不提供权限。跨会话总体认知继续经过公开性审核，主 agent 不能借记忆工具访问其他群的原始依据。

表情的客观内容描述与各群使用经验分开。主 agent 可以记录实际发送场景、群友反馈、适用时机，修正经验，或按群停用；没有反馈不能当作负面反馈。详见[表情收藏与使用](IMAGES.md)。

## 开发

`memory_tools.py` 提供 `manage_memory`，`read` 返回当前值、来源和版本，`write` 接受消息内部编号及完整新值。个人更新保存所选消息的原始依据到 `facts`，派生认知通过 `consolidation.py` 的指纹视图读取；群更新保存摘要、认知及来源快照。旧值与依据保存在变更历史中。

写操作使用项目锁和数据库事务，保护人工固定值；总体认知只允许读取、修正当前会话来源的自动部分。来源删除或修改使派生认知失效。主会话清除及重置继续让过期回合失效。

`data/knowledge-cleanup.json` 保存派生认知、依据指纹和历史。个人原始依据随数据库迁移；派生视图不迁移，目标部署根据原始依据重新整理。旧提取游标和失败批次仅为已有私有包迁移保留数据校验，不再发起提取请求，也没有恢复旧提取任务的入口。

工具通过 `tools.py` 注册到主 DSH 会话，不依赖发言是否成功。积极性为零时，普通消息仍可经分流触发记忆维护。轻量唤醒 API 不写记忆。后台模型建议继续只提供差异，维护者确认后保存。

名称展示继续由 `names.py` 将文字中的已知账号投影为平台昵称，结构化编号和工具参数保留原值；后台可编辑原文。名称不参与权限核验。

## 使用说明

重启机器人后，认知维护由主 agent 在对话中按需调用。旧的认知提取数量、独立输出上限、定时整理开关和间隔不再生效，后台不再提供这些配置。

后台个人及群页面继续查看当前有效认知、依据并手动固定。检查模型日志的 `manage_memory` 工具事件可区分成功、版本冲突、人工固定及无效依据；没有工具成功结果不能视为已保存。

验证：`python -m unittest tests.test_agent_memory tests.test_consolidation -q`，覆盖人工保护、版本冲突、群隔离、来源删除及派生视图失效。不通过真实 QQ 或 API 执行验证。
