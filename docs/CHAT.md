# 群聊与表情处理

## 设计

图片默认作为聊天内容理解，直接回应其情绪、事情或笑点，不先输出画面清单。识图、读字、描述、分析或排错语境按实际问题解释；纯图片不自动触发描述或询问用途。只依据可见内容回应，不能为接梗补造细节。内部安全审核与收藏描述仍保持客观，不作为聊天正文。

聊天环境不指定助手职业身份。模型结合人设选择参与方式和投入，合理求助通常接受，过分要求可拒绝；接受后保证事实与状态准确。核查工具服务于准备作出的事实回答或行动，随口接情绪不必检索。表达长短随语境和兴趣变化，默认不堆来源，明确索取来源或入口时可提供实际取得的必要链接。

表情是否使用由当前话题和人设偏好决定。接梗、赞同、无语、告别、回应表情时可以使用，接下认真求助后先回应问题。不按固定轮数强制发送；相关程度相近时优先避免最近重复，用户明确要同一张时允许复用。使用记录按机器人和会话隔离；图片客观描述保持公共，各群反馈和使用经验独立保存，可按群停用。

未知图片查看原图后可选择使用、记录描述或继续检索，不要求先记录才能聊天。已知图片含义不确定时可重新查看；已有描述的改动只提出建议，由维护者查看差异后确认。建议基于的描述已经变化时不得覆盖。

群内直接呼叫后的连续消息按发送者合并：等待最近一条补充后1.5秒，单批最多4秒。命令即时处理，不进入合并。其他人的话不合并进请求；同一人补充后停止尚未发送的旧回复，包括后续分条，已成功发送的消息不撤回。同发送者补充会停止旧回复，无关群消息不取消当前工作。

所有群采用固定话题策略：新话题达到本群最低参与人数后才考虑接话，之后每批新消息都持续评估，不要求新增成员；人数越多越倾向接话；机器人发言后仅在群友回应或讨论其说法时考虑续话。直接呼叫跳过门槛，全体提醒与普通消息使用同一策略。完整规则和后台日志见[群话题与回复策略](TOPICS.md)。

引用用于澄清回应对象，可以引用当前上下文内的较早消息；不存在的引用目标不允许使用。图片始终标记所属消息，引用图片与当前消息分开。

回复长度和分条由 agent 决定；发送层按平台长度完整拆包，不截掉正文，代码跨消息补齐围栏。合并转发只能读取当前实际收到的候选及由其发现的嵌套候选，转发身份、文字和指令都不授予权限。

认知整理仅凭明确的纠正或状态变化更新自动认知；时间久不等于无效，不能仅凭日期删信息。人工固定内容受保护，原始依据保留；整理结果变化记录前值与来源。

## 开发

- `emotes.py` 的检索支持空格分隔的关键词组合、常见情绪同义词和相关性排序；同分时最近十分钟用过的靠后，再按本会话累计使用次数排序。模型仍可选择最近使用的图。
- 图库 `.memory.sqlite3` 的 `emote_usage` 以独立事件编号记录成功发送、机器人、会话、图片哈希和时间。`service.py` 在平台发送成功后写入，失败不计数；统计写入失败不重发图片。`migration.py` 按事件编号合并，重复导入不重复计数。
- `inspect_emote` 仅接受本轮检索过的ID，沿用图片哈希检查、预览字节和工具调用预算。`remember_emotes` 首次记录写入 `emote_memory`；已有描述的修正写入 `emote_proposals`，包含原值与新值。并发维护描述时拒绝过期建议。
- `console_store.py` 仅在原值仍匹配时提供表情修正建议；后台沿用差异预览、版本检查和保存审计。建议和使用记录随图库数据库迁移。
- `groupchat.py` 为直接呼叫按发送者维护短时批次，并通过消息版本阻止过期副作用或发送，保留已有读取结果。分条之间留0.35秒接收新消息。主 agent 的 `set_response.quote_message_id` 仅允许当前上下文及实际引用中的消息ID。
- `message_context.py` 的 `mentions_all` 只检查当前 `original_message` 的 `at` 段且 `qq=all`；入口将该段呈现为“@全体成员”，归档仍保留 `mentions=["all"]`。不会将原生全体提醒判为 `explicit=true`，同时单独 @机器人时仍遵循直接呼叫规则。
- `groupchat.py` 按固定间隔合并普通群消息与全体提醒；由 `topics.py` 持久记录话题并执行人数及续话门槛。辅助 API 逐条分类，完整归档和模型上下文截取分开，详见[话题模块](TOPICS.md)。
- `llm.py` 在代码围栏外识别独占一行的 `<分条>`。不限制总条数；普通长文本继续按发送长度分包，代码围栏内标记保持原文。
- `forward.py` 的 `read_forward` 空ID列出候选，每轮最多24次平台读取、最多八层，offset分页每页30条，正文不按1500字裁剪。结果保留原发送者、昵称和引用提示，不把未读取图片当作已知图像。
- `vision.py` 为引用图片使用来源消息ID，未知ID保持未知。
- `consolidation.py` 在整理缓存中保留变更前值、更新时间和来源；有效性仍由现有来源指纹、会话边界及人工固定规则控制。

- 主 agent 获得话题判断与放行原因、`explicit`、`mention_all` 和复读候选。`response.py` 管理回应、静默、复读与引用选择；程序已通过话题门槛后，模型仍可保持沉默。

## 使用说明

拍一拍支持被拍后的按人设回应与当前会话内拍别人，规则和验证见 [拍一拍](POKE.md)。

重启机器人与后台后，在“话题日志”查看成功回复的话题及前后聊天。直接 @仍可回应，@全体不绕过话题规则。

更新后重启机器人与后台。人设中的“表情使用偏好”可在提示词管理调整；修改偏好不改变工具权限。已保存的本机系统提示词覆盖优先于代码默认值，如曾覆盖总体提示词，应在后台比较新默认规则后确认保存，避免丢失自定义内容。

表情管理中选择有重新识别建议的图片，点击“查看建议差异”，核对原图与前后描述后确认保存。只查看或生成建议不会替换描述；原值变化后旧建议不再显示。

验证建议：

1. 请求相同情绪的不同表情，查看候选是否包含使用次数；明确指定同一张应仍可发送。
2. 要求重新看一张已有描述的表情，检查后台建议，确认前原描述保持不变。
3. 在群里先@机器人，再于1.5秒内补充文字或图片，应合并回应；生成过程中补充同一问题，旧回复剩余分条应停止。
4. 询问较早消息或引用图片，检查引用目标及图片来源；模型未选择引用时不会强制引用。
5. 发送合并转发并询问内容，检查实际展开；读取失败只说明失败，不编造。此功能依赖NapCat返回合并转发内容，模拟测试不代表所有客户端格式均已实测。
6. 认知发生明确变更时检查整理结果及原始依据；人工固定内容和无明确变化证据的旧信息保持保护。
7. 验证本群人数门槛、达标后每批新消息均评估、发言后仅回应机器人相关讨论、直接 @绕过门槛。自动回归见 `tests/test_topics.py` 和 `tests/test_mentions_all.py`。

自动化回归见 `tests/test_chat_improvements.py`，其余发送、图库、迁移、后台和认知整理测试继续验证原有行为。实际模型决定是否用图和如何措辞，程序验证不保证每次生成选择完全一致。

图片表达验证：分别发送无配文的梗图、生活分享、带排错问题的截图和明确读字请求。前两类观察是否直接接内容，后两类检查是否准确回答所问；看不清时不得硬接不存在的梗。通用规则位于 `prompts/modules.json` 的总体回复提示词，小鲸鱼口吻示例位于 `personas/小鲸鱼.txt`。

图片作为独立消息留档，历史按需读取及权限规则见 [聊天图片](CHAT_IMAGES.md)。不再将前一张图片自动绑定到同一发送者的后续文字。
