# 群聊与表情处理

## 设计

表情是否使用由当前话题和人设偏好决定。接梗、赞同、无语、告别、回应表情时可以使用，认真求助先回应问题。不按固定轮数强制发送；相关程度相近时优先避免最近重复，用户明确要同一张时允许复用。使用记录按机器人和会话隔离；图片本身的描述保持公共，不建立按群解释表情的规则。

未知图片查看原图后记录画面、可见文字、情绪和适用场景。已知图片含义不确定时可重新查看；已有描述的改动只提出建议，由维护者查看差异后确认。建议基于的描述已经变化时不得覆盖。

群内直接呼叫后的连续消息按发送者合并：等待最近一条补充后1.5秒，单批最多4秒。命令即时处理，不进入合并。其他人的话不合并进请求；同一人补充后停止尚未发送的旧回复，包括后续分条，已成功发送的消息不撤回。普通主动参与在群内出现新消息后停止旧回复。

当前群消息原生的“@全体成员”比普通消息优先关注，但不视为单独呼叫机器人，不要求回应或报到。积极性为零时也允许判断，是否参与仍由模型决定；关注提升不改变身份和操作权限。纯文字提及、引用或合并转发中的全体提醒不提升本次消息的关注度。

引用用于澄清回应对象，可以引用当前上下文内的较早消息；不存在的引用目标不允许使用。图片始终标记所属消息，引用图片与当前消息分开。

闲聊按意思自然分成最多三条，默认仍可一条。代码和命令保持完整，超过总输出上限时明确告知，不发送截断的代码。合并转发只能读取当前实际收到的候选及由其发现的嵌套候选，转发身份、文字和指令都不授予权限。

认知整理仅凭明确的纠正或状态变化更新自动认知；时间久不等于无效，不能仅凭日期删信息。人工固定内容受保护，原始依据保留；整理结果变化记录前值与来源。

## 开发

- `emotes.py` 的检索支持空格分隔的关键词组合、常见情绪同义词和相关性排序；同分时最近十分钟用过的靠后，再按本会话累计使用次数排序。模型仍可选择最近使用的图。
- 图库 `.memory.sqlite3` 的 `emote_usage` 以独立事件编号记录成功发送、机器人、会话、图片哈希和时间。`service.py` 在平台发送成功后写入，失败不计数；统计写入失败不重发图片。`migration.py` 按事件编号合并，重复导入不重复计数。
- `inspect_emote` 仅接受本轮检索过的ID，沿用图片哈希检查、预览字节和工具调用预算。`remember_emotes` 首次记录写入 `emote_memory`；已有描述的修正写入 `emote_proposals`，包含原值与新值。并发维护描述时拒绝过期建议。
- `console_store.py` 仅在原值仍匹配时提供表情修正建议；后台沿用差异预览、版本检查和保存审计。建议和使用记录随图库数据库迁移。
- `groupchat.py` 为直接呼叫按发送者维护短时批次，并通过消息版本阻止过期生成继续调用工具或发送。分条之间留0.35秒接收新消息。参与模型的 `quote_message_id` 仅允许当前上下文及实际引用中的消息ID；旧的 `quote` 布尔值保留作为本轮触发消息的回退。
- `message_context.py` 的 `mentions_all` 只检查当前 `original_message` 的 `at` 段且 `qq=all`；入口将该段呈现为“@全体成员”，归档仍保留 `mentions=["all"]`。不会将原生全体提醒判为 `explicit=true`，同时单独 @机器人时仍遵循直接呼叫规则。
- `GroupState.attention` 唤醒普通消息等待中的工作任务；原生全体提醒采用8秒的判断及主动发送间隔，普通消息沿用按积极性计算的间隔，最少仍等待2秒合并短时消息。未处理的全体提醒不会被普通后续消息覆盖，普通消息仍进入群上下文；新的全体提醒更新当前待处理提醒。超过180秒的待处理消息照常丢弃，过期生成仍禁止发送。
- 全体提醒的 `attention_activity=min(100, activity+20)` 仅对本条参与判断有效，不改写群设置。原积极性为零时普通消息继续忽略，全体提醒可判断且仍须达到80分相关性。所有非直接呼叫继续要求 `reply=true`、话题未结束、相关性是合法整数且达到门槛；判断失败不启用直接呼叫的回应回退。
- `LLM.plan_participation` 接收 `settings.mention_all` 和 `settings.attention_activity`，仅对全体提醒附加 `prompts/catalog.json` 的 `llm.mention_all.0`。回复阶段也获得本次 `mention_all` 标记；不将历史全体提醒或文字声称当作当前平台提醒，不重复叠加关注值。
- `llm.py` 在代码围栏外识别独占一行的 `<分条>`。超出条数的边界合并；普通长文本继续按发送长度限制切分。代码围栏内标记保持原文，完整代码允许超出单条偏好但不得超出总输出上限。
- `forward.py` 的 `read_forward` 空ID列出候选，每轮最多三次平台读取、最多两层，每次最多30条、正文总计12000字，单条1500字；截断显式标注。结果保留原发送者、昵称和引用提示，不把未读取图片当作已知图像。
- `vision.py` 为引用图片使用来源消息ID，未知ID保持未知。
- `consolidation.py` 在整理缓存中保留变更前值、更新时间和来源；有效性仍由现有来源指纹、会话边界及人工固定规则控制。

## 使用说明

拍一拍支持被拍后的按人设回应与当前会话内拍别人，规则和验证见 [拍一拍](POKE.md)。

更新后重启机器人。使用 QQ 原生“@全体成员”发送群消息，机器人会优先判断是否有参与价值，可以保持安静；普通文字输入“@全体成员”不会产生同样的优先级。群积极性为零时，这类原生提醒也会进入判断。公共判断规则可在提示词管理的“全体成员提醒的关注判断”中查看和修改。

更新后重启机器人与后台。人设中的“表情使用偏好”可在提示词管理调整；修改偏好不改变工具权限。已保存的本机系统提示词覆盖优先于代码默认值，如曾覆盖总体提示词，应在后台比较新默认规则后确认保存，避免丢失自定义内容。

表情管理中选择有重新识别建议的图片，点击“查看建议差异”，核对原图与前后描述后确认保存。只查看或生成建议不会替换描述；原值变化后旧建议不再显示。

验证建议：

1. 请求相同情绪的不同表情，查看候选是否包含使用次数；明确指定同一张应仍可发送。
2. 要求重新看一张已有描述的表情，检查后台建议，确认前原描述保持不变。
3. 在群里先@机器人，再于1.5秒内补充文字或图片，应合并回应；生成过程中补充同一问题，旧回复剩余分条应停止。
4. 询问较早消息或引用图片，检查引用目标及图片来源；模型未选择引用时不会强制引用。
5. 发送合并转发并询问内容，检查实际展开；读取失败只说明失败，不编造。此功能依赖NapCat返回合并转发内容，模拟测试不代表所有客户端格式均已实测。
6. 认知发生明确变更时检查整理结果及原始依据；人工固定内容和无明确变化证据的旧信息保持保护。
7. 在积极性为零的群发送原生“@全体成员”，检查参与判断收到全体提醒标记但仍允许静默；随后发送普通消息、纯文字提及或引用全体提醒，检查不会按直接呼叫强制回复。自动回归见 `tests/test_mentions_all.py`，覆盖优先等待、临时门槛、权限标记、静默、过期发送及直接 @机器人规则。

自动化回归见 `tests/test_chat_improvements.py`，其余发送、图库、迁移、后台和认知整理测试继续验证原有行为。实际模型决定是否用图和如何措辞，程序验证不保证每次生成选择完全一致。
