# 本机管理后台

## 设计

后台用于本机维护机器人，不提供局域网或公网访问。菜单固定在左侧，右侧直接显示功能控件；窄窗口保持同样布局，菜单较多时在左侧滚动。

同一机器人账号的群聊和私聊共享记忆与认知。每个人按 QQ 维护一份统一档案，群号和私聊标记用于说明信息来源。群管理仅保留参与人数与插件配置；全部对话使用统一人设和机器人自身兴趣。群背景在记忆库中维护，不再提供群人设、群兴趣或重复的摘要认知表单。

记忆库按人物、主题、事件、群背景与表情聚合阅读，机器人档案显示当前自我档案和近期记录。空白字段、人工清空保护和内部索引默认隐藏，维护视图仍可核对。事实、事件、个人认知、想法、日记、自我档案、索引与会话背景保持各自含义。主观看法不能因整理而变成事实。记忆管理可以检索正文、查看来源与历史、编辑、固定、取消固定或归档；归档保留原文与历史，不做永久删除。

人工修改与模型建议均经过前后差异确认。修改正文会固定该记忆，固定空值同样保留；取消固定须单独保存。模型只提出当前选中资源的修改方案，不能执行后台写入或修改其他资源。后台记录旧值并检查版本；发生冲突时须重新读取。

个人档案的建议按该人的各群与私聊记录生成，不附无关人的私聊。群背景建议只附来源群的必要记录；单条记忆建议附当前笔记及其来源元数据。表情建议可以附原图，密钥不会返回浏览器。

后台与机器人独立运行。迁移要求机器人停止，后台可以保持打开。旧记忆未完成升级时，认知页面显示迁移入口，不将旧资料误显示为空档案。

## 开发

### 资源与接口

- `admin_server.py` 提供 FastAPI 服务，绑定 `127.0.0.1:8090`；`admin/console_endpoint.py` 保存共享监听地址。
- `admin/index.html`、`admin/app.js`、`admin/style.css` 提供原生浏览器界面，没有第三方 CDN 或前端构建依赖。
- `admin/console_store.py` 负责资源校验、版本摘要、写入、审计与撤销；`admin/console_settings.py` 维护模型配置、统一人设选择及插件设置。
- 个人资源 `person:<机器人QQ>:<用户QQ>` 返回统一平面字段，全部内容来自 `Vault.person`。个人编辑只替换修改的字段，保持其他笔记和依据不变。
- 群资源 `group:<机器人QQ>:<群号>` 仅包含参与人数；群背景通过记忆资源编辑。全局兴趣使用 `group_chat.json` 顶层 `interests`，默认设置接口同时维护统一人设与兴趣。
- 记忆资源 `memory:<机器人QQ>:<记忆编号>` 的可编辑值为 `content`、`state`、`fixed`；类型、主体、来源、历史与底层文件版本作为只读信息返回。类型为 `self`、`thought`、`diary` 的记录同时出现在机器人档案页。
- `GET /api/memories?query=...` 搜索名称、主体、来源与正文，最多返回 200 条；`POST /api/memories` 显式创建人工固定记录。通用 `GET/POST /api/resource` 读取和保存资源。
- `GET /api/navigation?section=base|groups|prompts` 分别返回账号与升级状态、群目录、人设与能力模块，不扫描全部记忆。浏览器按页面需要读取，目录缓存 30 秒，保存、删除与刷新后失效。
- `GET /api/memory-library` 支持类别、正文搜索、维护视图和分页，列表仅返回摘要；`GET /api/memory-library/detail` 按账号及档案键读取完整正文和依据，不附全部历史。历史与编辑仍通过单资源接口读取。
- 表情目录与操作记录分页返回，审计详情单独读取；话题沿用服务端分页。切页会取消旧页面的读取请求，并检查页面版本，避免较慢的旧请求覆盖当前页面。
- `GET /api/memory-activities` 通过时间及标识游标返回内容化活动摘要，默认每页 20 条；详情接口按需返回事件当时的前后变化与来源说明。整理完成事件通过明确的变更事件标识合并展示，不按时间邻近猜测关联。旧记录未保存快照时明确说明无法还原，不将当前正文当作历史。
- `GET /api/memory-status` 仅用于用户展开诊断后读取待核对冲突、来源失效、队列和索引状态，不阻塞活动首屏。普通召回、未保存信息、重复与内部维护活动不出现在活动列表，错误仍可见。
- `POST /api/memory-recall` 测试本地召回，返回选中内容、排除原因与字符预算，不调用模型、不发QQ、不写记忆；“提供给模型”不等同于模型采纳。
- `GET/POST /api/obsidian` 通过 `plugins/assistant/obsidian.py` 检测本机客户端、生成导航与图谱、创建编辑稿、核对差异和确认保存。编辑稿基线保存在 `data/memory-obsidian/<QQ>`；正式笔记、导航、图谱和工作台位于同一 Vault，后面三类通过 Vault 内 `.gitignore` 排除 Basic Memory 索引。派生图谱按同一人物或共同依据建立关系，不生成未经证实的社会关系。
- `GET /api/memory-upgrade` 预演旧记忆升级；`POST /api/memory-upgrade` 需要 `confirm=upgrade_memory`，执行离线备份、校验和发布。实现与命令行共用 `memory_upgrade.py`，不绕过运行锁。

### 数据与并发

统一记忆正文存放于 `data/memory-vault/<机器人QQ>/*.md`，不再由后台写入旧 `facts` 表。原始消息保留在 SQLite 中，来源使用平台消息身份及正文指纹。固定字段抑制同字段旧自动结果，人工清空不会让旧结论重新出现。

后台写入与记忆整理、迁移共用迁移锁；记忆库内部按文件版本检查并原子替换文件。保存前将原值、新值、时间与状态写入 `backups/admin-edits/`；撤销仍须匹配当前版本。新增记忆的撤销采用归档，保留内容；修改前版本还保存在笔记历史中。未完成的审计记录需要人工核对，不当作保存成功。

能力模块默认定义由 `prompts/modules.json` 管理，本机覆盖在 `data/console.json`。模块界面展示上下文正文、注入位置、工具说明与只读契约；编辑说明不会修改程序权限和参数结构。人设模板在 `personas/`，全局选择保存于 `group_chat.json`。模板新增、编辑、删除保留备份；默认模板与当前全局选中模板不能删除。

表情上传仅接受 PNG、JPEG、GIF、WebP，检查文件签名、大小与文件路径。表情描述按图片摘要关联，同图副本共享说明；描述和有依据的全局或用户反馈统一存入记忆库。表情页显示相关经验并链接到记忆资源，不再维护群使用经验的第二份认知。表情页不提供永久删除入口。

### 读取性能

记忆解析使用安全 YAML 加载器和有界内容缓存，每次仍读取实际文件内容，外部编辑或原子替换即时改变版本。返回值为独立副本，调用方不能污染缓存。来源有效性不跨请求缓存，遍历同一记忆库时复用数据库连接；来源被修订后仍立即失效。列表不携带完整历史；活动、档案和审计详情按需加载。有效变更与其他诊断分别保留最近 200 条，普通召回不会挤掉有效变更。

### 模型建议与预览

模型建议禁用工具，仅接受当前资源相同结构的完整值与说明。个人或群建议附按时间段及近期均衡抽样的依据，保留抽样数量、来源会话、消息编号、发送者及引用元数据；每个会话最多 120 条，总预算约 180 条。建议输出不合法时最多请求一次格式修正，失败不保存。

个人和群建议保存在 `backups/knowledge-proposals/`，同时记录资源版本与已有历史的摘要。新增聊天不直接使建议失效；已有依据被修改或删除、资源已变化时，保存前拒绝过期建议。单条记忆与其他资源的建议保留在当前页面，确认前不会写入笔记。

完整请求预览走正式组装逻辑，但截获发送而不调用模型。预览包含保存的人设、统一认知、历史问答、测试消息与工具；平台实时角色、图片、在线话题状态等不属于离线预览范围。人设检查与固定虚构场景试聊不修改记忆、不执行外部动作。

设置中的“重置全部 agent 会话”更新全局执行代际，下一轮重新读取当前资料。它保留聊天、记忆、人设与独立后台任务，不撤回已经执行的动作；在途旧回复在有效性检查后停止发送。

### 本机访问边界

服务检查 Host、Origin 与跨站请求来源；写请求携带当前后台实例的随机令牌。页面使用本地静态资源、内容安全策略和文本转义，不启用跨域访问。同一操作系统账户下的其他程序仍可能访问本机后台。

导入导出沿用同号合并、异号拒绝、显式目标账号、SQLite backup 与未完成事务恢复规则。ZIP 包含明文配置密钥；页面上传上限 512 MiB。迁移细节见 [数据迁移](MIGRATION.md)。

## 使用说明

1. 使用 `start.bat` 联合启动，或运行 `.\.venv\Scripts\python.exe admin_server.py`，访问 `http://127.0.0.1:8090`。
2. 如果页面提示旧记忆待迁移，先停止机器人，在“数据迁移”预演升级、查看报告并确认执行。后台继续运行；完成后再启动机器人。
3. “记忆库”按人物、主题、事件、群背景或表情筛选，先阅读聚合档案，再展开依据编辑具体记录。勾选“维护记录”核对固定空值、隔离内容和内部索引。
4. 选择具体记录后查看依据与历史；修改正文会固定，归档停止常规召回。仅取消固定时取消勾选后保存。“机器人档案”集中查看自我档案、想法和日记；新增记录需确认完整内容。召回测试可以检查某个问题将获得的内容及未选中原因。
5. “记忆活动”先看具体新增、修正与反馈摘要，时间为辅助信息；展开后查看前后变化和来源说明。无新信息的整理和普通召回不显示。点击“加载更早活动”继续阅读；只有展开诊断才检查队列与异常，页面不展示原始 JSON。不要将聊天中“记住了”的自然语言视为成功写入凭据。
6. “设置”选择统一人设并填写机器人自身兴趣，所有群聊和私聊共用；“提示词管理”编辑人设或能力模块。保存正文后后续请求生效；代码更新需要重启相关进程。
7. 手动编辑点击“保存”查看差异，模型建议点击“查看建议差异”，确认后才保存。操作记录支持在版本未变化时撤销。冲突时重新读取并核对差异，不强行覆盖。

验证：`python -m unittest tests.test_console tests.test_console_memory tests.test_console_loading tests.test_console_activity -q`；`node --test tests/admin_loading.test.cjs` 验证切页取消、迟到响应丢弃和导航失效。覆盖本机访问保护、模型建议不直写、统一群聊与私聊档案、人工固定空值、版本冲突、来源保留、记忆搜索与归档撤销、队列正文隔离及旧数据迁移提示。

### Obsidian 阅读与编辑

在“记忆库”点击 Obsidian，刷新导航后打开同一记忆库。首次使用需在 Obsidian 中把显示的目录打开为库；客户端未安装时页面会明确提示。关系图默认显示中文派生页面，可从人物、主题或事件进入原始依据。导航和图谱可重建；原始记忆仍是唯一事实来源。

编辑具体内容时，从记录旁点击“Obsidian 编辑稿”，修改工作台文件，再回后台读取待审稿、查看前后差异、确认保存。确认后正式记忆自动固定并保留旧版本。导航刷新或重复创建不会覆盖未保存稿件。源笔记或稿件在审阅后变化会拒绝过期保存；冲突时保留稿件供人工比较。

不要直接改动根目录的编号源笔记、基线文件或派生阅读页；工作台流程才提供后台固定保护与审计。此流程不把 Obsidian 变成文件系统权限沙箱。未确认的编辑稿不会被机器人召回。客户端关闭不影响机器人记忆运行。

验证：`python -m unittest tests.test_obsidian tests.test_console_memory tests.test_console -q`；`node --check admin/app.js` 检查前端语法。测试使用虚构库，覆盖聚合过滤、活动快照与旧记录说明、召回试验、全局兴趣、工作台不覆盖、确认保存与版本冲突；不代表已完成真实客户端视觉验收。

首次使用 Obsidian 必须登记仓库：后台复制完整仓库目录，点击“首次接入：打开仓库管理器”，在 Obsidian 选择“打开文件夹作为仓库”并选择该目录。完成后回后台点击“刷新接入状态与待审稿”；之后可直接打开导航和编辑稿。安装软件、注册协议或生成导航都不等于登记仓库。后台只读检测客户端登记，不修改客户端全局配置。打开按钮通过已鉴权的本机后台调用系统启动 Obsidian，不依赖浏览器跳转外部协议；页面会显示请求结果，启动失败时提示检查安装。
