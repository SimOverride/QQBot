# 本机自主任务

## 设计

机器人可委托本机开发执行器完成任务或开发群插件。聊天、审批、执行、补充和结果使用统一任务台账，机器人依据执行事件回答进度，不推测完成百分比。所有群与账号共享一条执行队列，默认同时执行两个任务；插件测试也占用任务名额。

群管理员、群主和机器人主人可以申请。非主人请求先保存为不可执行的申请，私发主人完整需求和本机执行风险，主人在私聊批准后才创建任务。主人自己的请求直接排队。其他群、其他机器人账号不能查看或操作该任务；主人私聊可管理本机器人全部任务。回复阶段提供任务工具，由聊天模型识别当前发起人的明确委托；不以是否 @ 作为工具可用条件，身份、范围和审批仍由工具核验。

已批准任务的补充要求无需再次审批，执行期间直接送入执行器；已完成、失败或中断的任务可通过补充继续。待审批申请不能暗中更改，需取消后重新申请。取消不能撤销已经发生的外部操作；中断任务不自动重跑。

插件在后端复测通过后自动发布到原群，不增加发布审批。原群绑定不能由模型或插件返回值改写，后续版本保留已有开关和群数据，失败版本不替换原版本。生成插件运行在独立进程，不能在机器人主进程中导入。

本机执行并非安全沙箱。执行器采用工作目录写入策略，关闭提权交互；生成的 Python 代码与测试仍具有当前系统用户的本机权限，不能保证抵抗恶意代码。独立目录、精简环境、输出校验和哈希检查不是操作系统安全隔离。只批准可信任务，不向任务提供聊天数据库、QQ 凭据或其他群上下文。

## 开发

- `plugins/tasks/store.py` 使用 `data/tasks.sqlite3` 存储申请、执行任务和事件；审批消费与任务创建在同一事务中完成。申请以 `a_`、任务以 `t_` 开头。
- `plugins/tasks/manager.py` 提供 `manage_task` 模型工具与 `/任务` 确定性命令，按真实身份核验权限。队列按入库顺序调度。通知结果记录为待发、尝试中、已发、主 agent 静默或结果不明；结果不明不盲目重发。
- `plugins/tasks/runner.py` 通过客户端随附运行时启动本机 dsh，固定兼容客户端 `0.2.1-rc.2`，不自动升级个人安装。每任务使用独立 Harness 配置目录，不加载个人插件。凭据仅向子进程传递 DeepSeek API 密钥，关闭遥测；不转发完整机器人环境。
- `plugins/tasks/bridge.mjs` 使用本机 agent API，将补充需求送至下一步骤边界，转发公开回复、工具调用、工具结果、待办、Token 用量及结束原因，不转发内部推理。stdin/stdout 使用有界 JSON 行协议，退出和取消回收本任务进程树。
- `plugins/assistant/service.py` 在回复上下文中注入当前范围的任务状态；`groupchat.py` 在参与判断中加入同范围状态；模型可查询最近事件获取细节。通知成功时写入消息归档。
- `plugins/tasks/generated.py` 在 `data/generated/插件编号/内容哈希` 上独立复测，实际运行的单元测试通过且 JSON 协议冒烟通过才发布，不按凑足固定测试数量验收。相同内容版本哈希验证后通过独立 Python 进程调用，超时或输出超限终止。
- 工作产物位于 `data/task-workspaces/任务号/work`，运行配置与 dsh 原生会话位于相邻 `home`。生成插件配置仍在 `data/plugins.json`，范围仅含原始群，数据包含版本元信息与业务状态。
- 任务台账、工作产物、发布版本纳入私有迁移；dsh 原生会话及运行配置不迁移。SQLite 使用 backup。目标记录优先，导入的未结束执行任务设为中断，必须明确继续；源机器路径和安装不自动适配。
- `MODEL_TRACE_ENABLED` 控制诊断事件文件，默认开启。关闭诊断不删除任务运行所需的业务台账。固定执行约束仅记录版本，动态需求、补充、步骤、结果和错误保留，经凭据过滤后记录。

### 自然语言任务路由

主 DSH agent 根据当前用户诉求、连续会话和实际可用工具处理：明确后台执行或开发交付请求通过 `manage_task` 申请任务；仅咨询方案或仅索要源码时不申请。试玩链接作为交付要求传给执行器核实托管条件，不提前承诺公开访问，也不据此拒绝开发。

`llm.tasks.0` 和 `chat.modules` 维护执行意图与模块协作规则。任务工具只在有任务会话的回复阶段提供，沿用工具侧权限和主人审批。修改代码后重启机器人；可通过模型诊断日志检查是否调用 `manage_task` 以及返回的实际状态。回归测试为 `tests/test_task_routing.py`，验证主 agent 的能力发现与工具权限；模型遵循效果需实际群聊验收。

### 默认任务上下文

普通回复只附加一次至多六条可见任务的简短状态，保留目标、状态和时间，不附加源码、完整结果或执行事件。已结束且已通知的任务退出默认上下文，台账与查询能力保留；未通知的结束任务仍可见。参与判断不注入任务台账。此筛选不禁止模型自然提及相关旧任务。

任务状态变化同步写入原会话模块事件。终态通知由主 DSH agent 在原群/私聊持续会话中决定文字或静默；事件本身不提供新用户授权，通知回合不挂载任务修改及插件执行工具。主人审批通知保留确定性发送。

## 使用说明

任务创建默认只简短确认需求及必要的待审批状态，不主动罗列编号、执行流程、文件格式或验收标准；确实缺少影响执行的信息时才询问。排队和启动不重复通知。完成时以“这是结果：”直接给出实际成果、结论或可用入口，不附带技术报告；完整记录仍保留，用户追问或主动查看任务时再提供。失败或中断不能伪装完成，审批私信仍保留必要审核信息。

本机安装 DeepSeek Harness 客户端 `0.2.1-rc.2`。使用 `.env` 的 `DEEPSEEK_API_KEY`，聊天与任务共用 `DSH_MODEL`，默认 `deepseek-flash`。安装定位及版本校验见 [DSH 聊天执行](DSH.md)。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `TASK_MAX_CONCURRENCY` | `2` | 全部群共享，范围 1 至 16 |
| `TASK_TIMEOUT_SECONDS` | `3600` | 单次 dsh 执行时限 |
| `TASK_MAX_STEPS` | `256` | 单次 dsh 步骤预算 |
| `DSH_PACKAGE_DIR` | 空 | 自动查找客户端，可指定客户端安装目录或可执行文件 |
| `DSH_MODEL` | `deepseek-flash` | 聊天与任务模型 |

修改配置后重启机器人。群内先 @机器人，自然语言说明执行需求，例如“帮本群开发一个记分插件”。只是询问方案不会主动创建任务。

| 操作 | 示例 |
| --- | --- |
| 查看本群任务 | `/任务` 或“你现在在做什么任务？” |
| 查看详细状态 | `/任务 查看 t_编号` |
| 请求普通执行 | `/任务 执行 分析这些数据并生成报告` |
| 请求群插件 | `/任务 开发 一个记分插件` |
| 主人私聊审核 | `/任务 批准 a_编号` 或 `/任务 拒绝 a_编号` |
| 补充或继续 | `/任务 补充 t_编号 增加导出功能` |
| 取消 | `/任务 取消 t_编号` |

插件发布后可自然语言调用，或 `/gen_编号 具体操作`。使用 `/插件 本群 gen_编号 关闭` 停用；主人可用全局开关。首版生成插件支持按需工具调用和群内持久化数据，不自动注册定时触发、消息订阅或任意 QQ API；定时消息继续使用已有定时插件。

审批私信发送失败时申请仍不执行，主人可私聊 `/任务` 查看申请并审核。失败细节通过任务查询读取，不把“模型说完成”当作发布成功。测试或发布期间请等状态结束再补充；取消后需另行申请新任务。

验证：`.venv/Scripts/python.exe -m unittest tests.test_tasks -v`。真实本机端到端验证使用 `.venv/Scripts/python.exe -m tests.smoke_dsh`，会消耗 API 用量，使用临时目录，不发 QQ 消息。

聊天回复阶段可在未 @ 的连续对话中识别明确任务或插件委托并调用工具，参与判断仅决定是否回复及提供指代参考。工具始终绑定当前真实发起人和会话，沿用原有身份权限与审批；普通闲聊、引用或旧任务不构成新操作授权。模型提示 `llm.action_intent.0` 管理此意图边界。
