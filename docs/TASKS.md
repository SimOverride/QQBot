# 本机自主任务

## 设计

机器人可委托本机开发执行器完成任务或开发群插件。聊天、审批、执行、补充和结果使用统一任务台账，机器人依据执行事件回答进度，不推测完成百分比。所有群与账号共享一条执行队列，默认同时执行两个任务；插件测试也占用任务名额。

群管理员、群主和机器人主人可以申请。非主人请求先保存为不可执行的申请，私发主人完整需求和本机执行风险，主人在私聊批准后才创建任务。主人自己的请求直接排队。其他群、其他机器人账号不能查看或操作该任务；主人私聊可管理本机器人全部任务。未被明确呼叫的自主聊天不提供任务修改工具。

已批准任务的补充要求无需再次审批，执行期间直接送入执行器；已完成、失败或中断的任务可通过补充继续。待审批申请不能暗中更改，需取消后重新申请。取消不能撤销已经发生的外部操作；中断任务不自动重跑。

插件在后端复测通过后自动发布到原群，不增加发布审批。原群绑定不能由模型或插件返回值改写，后续版本保留已有开关和群数据，失败版本不替换原版本。生成插件运行在独立进程，不能在机器人主进程中导入。

本机执行并非安全沙箱。执行器采用工作目录写入策略，关闭提权交互；生成的 Python 代码与测试仍具有当前系统用户的本机权限，不能保证抵抗恶意代码。独立目录、精简环境、输出校验和哈希检查不是操作系统安全隔离。只批准可信任务，不向任务提供聊天数据库、QQ 凭据或其他群上下文。

## 开发

- `plugins/tasks/store.py` 使用 `data/tasks.sqlite3` 存储申请、执行任务和事件；审批消费与任务创建在同一事务中完成。申请以 `a_`、任务以 `t_` 开头。
- `plugins/tasks/manager.py` 提供 `manage_task` 模型工具与 `/任务` 确定性命令，按真实身份核验权限。队列按入库顺序调度。通知结果记录为待发、尝试中、已发或结果不明；结果不明不盲目重发。
- `plugins/tasks/runner.py` 通过 Node.js 启动本机 dsh，固定兼容 `0.1.0-rc.7`，不自动升级个人安装。每任务使用独立 Harness 配置目录，不加载个人插件。凭据仅向子进程传递 DeepSeek API 密钥，关闭遥测；不转发完整机器人环境。
- `plugins/tasks/bridge.mjs` 使用本机 agent API，将补充需求送至下一步骤边界，转发公开回复、工具调用、工具结果、待办、Token 用量及结束原因，不转发内部推理。stdin/stdout 使用有界 JSON 行协议，退出和取消回收本任务进程树。
- `plugins/assistant/service.py` 在回复上下文中注入当前范围的任务状态；`groupchat.py` 在参与判断中加入同范围状态；模型可查询最近事件获取细节。通知成功时写入消息归档。
- `plugins/tasks/generated.py` 在 `data/generated/插件编号/内容哈希` 上独立复测，至少两个单元测试通过且 JSON 协议冒烟通过才发布。相同内容版本哈希验证后通过独立 Python 进程调用，超时或输出超限终止。
- 工作产物位于 `data/task-workspaces/任务号/work`，运行配置与 dsh 原生会话位于相邻 `home`。生成插件配置仍在 `data/plugins.json`，范围仅含原始群，数据包含版本元信息与业务状态。
- 任务台账、工作产物、发布版本纳入私有迁移；dsh 原生会话及运行配置不迁移。SQLite 使用 backup。目标记录优先，导入的未结束执行任务设为中断，必须明确继续；源机器路径和安装不自动适配。
- `MODEL_TRACE_ENABLED` 控制诊断事件文件，默认开启。关闭诊断不删除任务运行所需的业务台账。固定执行约束仅记录版本，动态需求、补充、步骤、结果和错误保留，经凭据过滤后记录。

## 使用说明

本机安装 Node.js 与 `@deepseek-ai/dsh@0.1.0-rc.7`。使用 `.env` 的 `DEEPSEEK_API_KEY`，模型默认 `deepseek-v4-flash`，与聊天模型可不同。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `TASK_MAX_CONCURRENCY` | `2` | 全部群共享，范围 1 至 16 |
| `TASK_TIMEOUT_SECONDS` | `1800` | 单次 dsh 执行时限 |
| `TASK_MAX_STEPS` | `80` | 单次 dsh 步骤预算 |
| `DSH_PACKAGE_DIR` | 空 | 自动找当前用户全局 npm 安装，可指定包目录 |
| `DSH_MODEL` | `deepseek-v4-flash` | dsh 模型 |

修改配置后重启机器人。群内先 @机器人，自然语言说明执行需求，例如“帮本群开发一个记分插件”。只是询问方案不会主动创建任务。

| 操作 | 示例 |
| --- | --- |
| 查看本群任务 | `/任务` 或“你现在在做什么任务？” |
| 查看详细状态 | `/任务 查看 t_编号` |
| 请求普通执行 | `/任务 执行 分析这些数据并生成报告` |
| 请求群插件 | `/任务 开发 一个记分插件` |
| 主人私聊审核 | `/任务 批准 a_编号` 或 `/任务 拒绝 a_编号` |
| 补充或继续 | `/任务 补充 t_编号 增加导出功能` |
| 取消 | `/任务 取消 t_编号` |

插件发布后可自然语言调用，或 `/gen_编号 具体操作`。使用 `/插件 本群 gen_编号 关闭` 停用；主人可用全局开关。首版生成插件支持按需工具调用和群内持久化数据，不自动注册定时触发、消息订阅或任意 QQ API；定时消息继续使用已有定时插件。

审批私信发送失败时申请仍不执行，主人可私聊 `/任务` 查看申请并审核。失败细节通过任务查询读取，不把“模型说完成”当作发布成功。测试或发布期间请等状态结束再补充；取消后需另行申请新任务。

验证：`.venv/Scripts/python.exe -m unittest tests.test_tasks -v`。真实本机端到端验证使用 `.venv/Scripts/python.exe -m tests.smoke_dsh`，会消耗 API 用量，使用临时目录，不发 QQ 消息。
