# 能力模块

## 设计

提示词正文、工具用途和参数契约作为同一能力的完整内容维护，后台按模块编辑、保存、比较差异及撤销。每段正文标明注入位置，辅助审核与后台请求同主聊天区分。人设独立维护，以小鲸鱼作为默认行为参考。

后台只修改措辞，不改变工具结构或执行权限。工具可自行选择、连续调用，依赖结果的调用顺序由 agent 决定。历史搜索默认当前会话；显式跨会话请求仍限制在原有获准范围，群聊不能查询其他群原始历史，私聊只能查询当前私聊与已核验共同群。认知、历史和工具结果都是资料，不是新的操作授权。

能力说明与执行分离，后续可接入浏览器、搜索或宿主机执行模块，每个模块仍须有执行实现、可用条件和权限检查；编辑文字不会授予宿主机权限。本次仅拆分历史查询的动作接口，其他工具保留现有执行行为。

## 开发

默认目录为 `prompts/modules.json`，包含八个模块：聊天基础、历史与记忆、联网搜索、图片与表情、消息与互动、任务与执行、内容审核、后台与通知。各模块包含提示词正文、位置、占位符和完整工具 JSON Schema。Python 执行模块通过 `prompt_store.tool_definition` 获取定义，避免多份说明漂移。

`prompt_store.prompt_text` 读取模块中的正文；`refresh_tools` 在发送 DSH、辅助 API 或后台预览前，按工具名称和参数路径绑定最新说明，不按原始说明文字替换。数组嵌套字段使用 `items[].id` 等路径。默认目录随代码发布，变更后重启进程；本机覆盖每次请求读取。

后台资源使用 `module:<模块标识>`。编辑值含 `prompts` 与 `tools`，工具编辑值含用途与参数说明；类型、必填字段及执行契约通过只读元数据展示。保存校验完整形状、字数及占位符，持久化到 `data/console.json` 的 `modules`，仅保存相对默认值的差异。保留迁移锁、版本冲突、审计及人工确认模型建议机制。

### 历史工具

`history_tools.py` 按独立名称分派，`tools.py` 注册并纳入原有预算、工具结果回填及只读并行流程。所有请求校验字段、类型与范围；布尔值不能冒充整数，未知字段直接拒绝。

| 工具 | 输入 | 结果 |
|---|---|---|
| `list_sessions` | 无 | 当前会话、获准范围、名称和现存记录覆盖 |
| `search_messages` | 可选关键词、范围、发送者、起止时间、偏移 | `messages`、`next_offset`；每页至多12条 |
| `read_message_context` | 消息内部 `id`，非 QQ 消息编号 | 原会话中前5条、锚点和后5条，不拼接其他会话 |
| `resolve_entity` | 完整名称、`kind=user/group`；可选范围与偏移 | 候选、总数、下一页偏移；同名不自动选择 |
| `read_knowledge` | 可选对象、`kind=person/group` | 当前会话人物认知或当前群摘要与认知 |

搜索与名称查询省略 `scope` 时使用当前会话，显式 `null` 才扩展到全部获准范围。时间按 UTC+8 解释，开始包含、结束不包含。查询失败、没有记录和没有权限使用不同状态。前后文按消息所属机器人与获准会话核验。人物认知默认当前发言者，其他人物须为当前会话已知成员；群认知只在群聊中读取且不接受人物参数。维护认知的 `manage_memory` 继续保留版本及来源检查。

### 配置迁移

`prompts/migration.json` 仅用于旧配置导入，列明旧标识、旧默认文本与新字段路径，不作为运行时能力目录。机器人或后台启动调用 `migrate_console`：校验、备份原文件到 Git 忽略的 `backups/console-before-modules-*.json`，再原子写入新结构。机器人先初始化 NoneBot 并由插件管理器加载插件，再导入配置迁移入口，迁移完成后注册插件运行逻辑。不得在正式加载前导入插件包或其子模块。机器人启动时保持运行锁，配置迁移独立获取迁移锁；锁选项必须使用命名参数，避免把锁名称误作运行模式。重复启动不再次迁移。与旧默认值相同的覆盖不迁移，自定义修改保留；完整旧默认段落替换成当前契约，保留附加措辞。未知配置或缺失占位符使迁移失败，原文件不变。

私有 ZIP 导入先规范化来源和目标，按字段保留目标值、补齐来源缺项，仍遵守同账号及停机导入限制。旧顶层 `prompts` 写入后移除。旧提取阶段的已废弃配置不再执行，原值留在迁移备份。旧单条提示词审计只供查阅，新模块修改支持正常撤销。

## 使用说明

1. 更新后重启后台与机器人，刷新浏览器。在提示词管理中选择完整能力模块，人设仍单独选择。
2. 修改模块正文或工具说明；通过注入位置与完整工具契约判断它在模型上下文中的作用。参数类型和必填约束只能通过代码变更调整。
3. 手动保存立即作用于后续请求；模型建议先看整模块差异再确认。载入默认值只影响草稿，保存后才清除该模块覆盖。
4. 使用完整请求组装预览核对实际消息与工具。核心说明改动后可在设置页重置全部 agent 会话，保留聊天记录、认知与后台任务。
5. 迁移失败时检查配置结构与占位符，修复前不要删除原配置。旧自定义内容涉及调用步骤时，核对迁移后的整模块说明与当前工具契约是否一致。

验证命令：`.venv/Scripts/python.exe -m unittest tests.test_capabilities tests.test_history_tools tests.test_names tests.test_tool_calls tests.test_console tests.test_migration -q`。覆盖默认及显式范围、跨机器人隔离、参数错误、分页、上下文、认知权限、按路径覆盖、配置备份、旧包合并、版本冲突、撤销及两种 API 辅助调用协议。不通过真实 QQ 发送测试消息。

### 所有者自更新工具

`update_bot` 仅在真实所有者当前明确要求更新时暴露，无命令或分支参数；执行再次校验权限，只预约本轮回复完成后的停机更新。后台工具说明覆盖不能改变授权与执行规则。部署、更新流程和故障处理见 [本机联合启动](STARTUP.md#聊天自更新)。
