# QQBot

## 可视化后台

双击 `start.bat` 统一启动后台、NapCat 和机器人，并打开本机后台：`http://127.0.0.1:8090`。
机器人所有者可发送 `/后台` 或“后台入口在哪里”查询地址，只能在运行机器人的电脑上打开。
可查看和修正个人认知、群摘要与群认知、聊天记录、表情内容记忆、总体和各阶段提示词，
也可导出或导入迁移包。每个编辑器支持手动修改或对话生成建议，查看前后差异并确认后才保存。
后台独立运行，导入时先停止机器人。首次升级后重新启动机器人以加载后台维护支持，
以后保存提示词与认知无需重启。完整说明见 [后台文档](docs/CONSOLE.md)。

## 机器迁移

使用 `migration.py export` 导出全部私有数据为普通 ZIP；停止目标机器人后，
使用 `migration.py import "备份.zip"` 合并同一账号数据。新部署必须加
`--bot-qq 目标机器人QQ`；不同账号拒绝导入。导入前自动备份，异常支持恢复。
完整命令、合并规则和范围见 [迁移模块文档](docs/MIGRATION.md)。
备份包含 `.env` 明文密钥与聊天记录，默认保存到 Git 忽略的 `backups/`。

私人 QQ 小群 AI 助手：Python 3.12、NoneBot2、OneBot v11、HTTPX。

已实现 DeepSeek / OpenAI 官方 API、自然语言意图理解、模型自主搜索、短期会话、显式 @、限流、去重和错误处理。已通过本地测试并连接 NapCat；搜索仍取决于本地搜索服务配置。

## 使用方式

在机器人已加入的群里直接 @机器人说话；也可以只 @ 而不附加问题，机器人会结合当前话题或本地人设自由发挥：

- `@机器人 帮我看看这个方案有哪些漏洞……`
- `@机器人 吐槽一下这段观点……`
- `@机器人 最近这项技术有什么进展？`
- `@机器人 那它和刚才那个有什么区别？`

不需要记住分析、锐评、搜索命令。模型自行决定回答方式及是否调用搜索。
所有固定指令必须以 `/` 开头。群内管理指令仍需 @机器人；`/积极性` 可直接在群里发送。普通聊天不需要 `/`，由机器人判断是否参与，@可直接触发。

| 权限 | 指令 |
| --- | --- |
| 所有成员 | `/ping`、`/帮助`（别名 `/help`） |
| 群主、群管理员、机器人所有者 | `/清空`（自己的本群记忆）、`/清空 @某人`、`/清空 本群` |
| 机器人主人 | `/清空全部`（本机器人所有群） |

批量清空先返回确认码，发起者需在同一群60秒内发送 `@机器人 /确认 确认码`。
确认码只能用一次；新操作覆盖旧确认；确认时重新核验权限。等待在途会话超时则不删除，需重新发起。
`/帮助` 只显示有权使用的指令。未知 `/指令` 不交给模型；不带 `/` 的“清空”等按聊天处理。
群主和群管理员拥有本群管理权限，机器人所有者拥有最高权限。机器人主人在 `.env` 设置
`BOT_OWNERS=[你的QQ号]`，修改后重启。默认空数组，不自动把机器人账号或任何群成员设为主人。

从启用起采集机器人已加入的群内全部新消息（无需@），未@消息由模型判断是否参与，显式@仍直接触发。文本保存全文；图片保存类型和占位标记，由支持图片输入的聊天模型直接理解；语音、附件暂不识别。

## 本地运行（PowerShell）

已配置好环境后，双击根目录的 `start.bat` 即可启动机器人。脚本自动切换到项目目录，
检查虚拟环境和 `.env`，并保留控制台以查看运行状态或错误。运行期间保持窗口开启，
按 `Ctrl+C` 停止。首次运行输入 NapCat 启动文件路径，之后自动启动或复用 NapCat；未登录时仍需扫码。
启动路径和本机探测端口统一保存在 `.env` 的 `NAPCAT_LAUNCHER`、`NAPCAT_PORT`，可参考 `.env.example` 修改。默认探测端口为 6099，请与 NapCat WebUI 端口保持一致。
详细配置和排查见 [联合启动说明](docs/STARTUP.md)。
启动脚本会识别本项目已经运行的机器人；再次双击会停止旧机器人后重启，内存缓存和待确认操作清空，历史消息与长期认知仍保留。不会关闭QQ、NapCat或其他项目的Python进程。
`start.bat` 调用同目录的 `start.ps1` 和 `scripts/napcat.ps1`，请一并保留。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

如果已有 `.env`，保留原文件，参照模板补齐字段。

在 `.env` 填写：

1. 将机器人加入需要聊天的 QQ 群，无需配置群名单。
2. `ONEBOT_ACCESS_TOKEN`：自行生成的随机长 Token，与 NapCat 保持一致。
3. `LLM_PROVIDER=deepseek` 或 `openai`。
4. 对应的 `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` 或 `OPENAI_API_KEY` / `OPENAI_MODEL`。模型 ID 填你账户实际可用且支持工具调用的模型，不默认替换模型。
5. 可选 `SEARCH_API_KEY`：Tavily Key。缺失时搜索关闭，普通聊天仍可用，模型会被告知不能联网。

旧版本预留的 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 不再使用；请迁移到上述字段。
两套凭据可以同时保存，通过 `LLM_PROVIDER` 选择，修改后重启生效。不自动切换服务商或失败重试。

```powershell
.\.venv\Scripts\python.exe bot.py
```

NapCat 需另外安装并登录专用 QQ 账号。在其 WebUI 创建 WebSocket 客户端：

| 项目 | 值 |
| --- | --- |
| 地址 | `ws://127.0.0.1:8080/onebot/v11/` |
| Token | 与 `ONEBOT_ACCESS_TOKEN` 一致 |
| 消息格式 | `array` |

本机双进程部署无需开放公网端口。先发送 `@机器人 /ping`，再测试自然语言提问及联网问题。

## 默认限制

- 会话按机器人、群、用户隔离，最多 8 轮、12000 字符，30 分钟过期，重启后从SQLite恢复。
- 单条输入最多 4000 字符，用户冷却 5 秒，全局最多同时处理 2 个模型工作流。
- 等待锁或并发额度最多 3 秒，最多接纳 32 个待处理业务请求。
- 每次回答最多搜索 2 次，每次最多 5 条结果；模型单次超时 60 秒，完整工作流最多 180 秒。
- 输出预算 2048 token，发送最多 3 条、每条 1500 字符；超出时明确标注截断。
- 清空与回答共用会话锁；若等待超时会提示重试，不会假称清空成功。
- 仅在全部回复发送成功后保存完整问答；发送失败不盲目重发。

OpenAI 使用 Responses API，关闭服务端响应存储；DeepSeek 使用 Chat Completions，首期显式关闭思考模式，以只保存可见问答的方式维持短期上下文。
联网回复根据实际搜索结果直接解释，不展示参考链接、来源列表或引用编号；资料不足时说明不确定性。回答质量和搜索时机仍需真实模型验收。

日志位于 `logs/qqbot.log`，5 MB 轮转、最多保留 5 个归档。业务日志只保存请求 ID、模式、耗时、状态码和 token 用量；默认屏蔽可能含原始事件的框架消息和适配器日志。不会记录完整群聊或密钥。

## 本地人设与对话风格

- `personas/`：人格提示词文件夹，`默认.txt` 为默认人设。
- `styles/`：说话风格提示词文件夹，`默认.txt` 为默认风格。
- 每个选项是一个 UTF-8 的 `.txt` 文件，正文1～4000字；文件名（不含扩展名）即切换名称。

这两个文件作为全局默认，只在本地编辑和查看。群管理员、群主和机器人所有者可在本群
@机器人使用以下指令切换本群设定：

- `/人格 列表`（别名 `/人设`）、`/风格 列表`：查看当前选项和预设名称。
- `/人格 切换 幽默群友`：人格预设包括友善助手、理性顾问、幽默群友、温柔陪伴。
- `/风格 切换 温柔`：风格预设包括自然简洁、温柔、幽默、严谨、详细。
- 新增和修改提示词只能在本地文件夹操作；聊天不支持设置或编辑正文。
- `/人格 默认`、`/风格 默认`：分别恢复使用本地默认。

群设定只把选中的文件名保存在本地 `group_chat.json`，后续请求生效并跨重启保留，其他群和私聊不受影响。
新增文件后列表自动更新；已选文件修改后下次请求读取最新正文。删除已选文件会报配置错误，可切换到默认恢复。
普通回复、主动参与判断和程序提示使用本群设定；私聊继续使用本地默认。
指令须在目标群执行，不支持私聊修改群配置。列表只显示选项名称，不导出配置正文。
本地文件保存后下次模型请求自动读取，无需重启；已经开始的回答继续使用原设置。
设置不会清空对话记忆。文件缺失、空白、过长或编码错误时启动会失败；运行中发生错误则提示本次处理失败，不发送配置内容。
基础真实性、工具权限和长度限制始终保留。模型被要求不披露本地提示词，但提示词会发送给模型服务商，勿在其中放入密钥等秘密。

## 长期记忆

数据保存在 `data/memory.sqlite3`（SQLite），重启不丢失，默认不自动删除。仅采集机器人已加入的群，从启用后开始；不补抓过去历史。
所有消息按机器人、群号、发送者QQ号和消息ID记录，重复上报不会重复存储。
成功发送的完整问答另存为会话记录；用户原始发言即使模型失败也会保留在群消息档案里。

每次提问恢复最近的完整问答，并从该用户在本群最近1000条消息/问答中按关键词寻找相关片段。
所有历史仍在本地数据库，但不会一次全部发给模型。个人按机器人与 QQ 集中为两层认知：总体资料跨会话使用，私聊及各群的角色、关系和习惯仅用于对应会话；不同成员始终隔离，不根据他人的评价推断本人。自动提取的总体资料跨来源使用前仍需公开审核，后台明确确认的总体资料直接生效。
每60秒检查一次积压，每轮最多处理2名成员，每批最多20条、8000字符。
默认同一成员积累10条新消息才提取认知，通过 `MEMORY_PROFILE_MIN_MESSAGES` 调整；提取会额外消耗模型额度。
个人认知保存一段跨会话总体认知，以及一段私聊印象；各群保留角色、互动习惯、互动关系、补充认知四项分类；后台按平台昵称列出个人，用群名展示会话子菜单并支持按群筛选。
这些是可能过时的用户自述，不是已核实事实；没有证据的提取结果不会写入。

| 指令 | 权限与作用 |
| --- | --- |
| `/记忆` | 所有人可查看自己在本群的认知及消息数量；结果会发到当前群 |
| `/记住 总体认知 喜欢摄影，偏好简洁回答` | 群主、群管理员或所有者替换本人总体认知；使用“会话印象”替换当前会话全部印象；群内可使用角色、互动习惯、互动关系、补充认知独立修改对应分类 |
| `/忘记 总体认知` 或 `/忘记 会话印象` | 群主、群管理员或所有者删除对应认知，群内可指定分类单独删除；不删除历史，未来新消息可重新形成认知 |
| `/清空`、`/清空 @某人` | 沿用管理权限，删除该用户在本群的会话、消息档案、会话认知和依赖这些原文的自动总体认知；手动确认的总体资料保留 |
| `/清空 本群`、`/清空全部` | 沿用分级权限及60秒确认，删除对应范围的长期数据 |

清空只影响当前已存数据，后续新消息继续采集。程序不会从旧档案重新批量提取刚被手动修正/删除的认知，
但尚保留的历史仍可作为回答背景；希望彻底忘记时使用有权限的 `/清空`。
数据库留在本机且不提交Git。需要备份时先停止机器人，再备份数据库；运行时的WAL文件也是数据库的一部分。
群内可查看人格/风格的选项名称；长期记忆不能改变权限或人设配置。

## 身份与权限

新采集消息保留发送者 QQ、当时昵称、被 @ 对象和引用来源；机器人回复保留触发消息及关联用户。
近期群聊上下文与历史查询使用相同的归属信息，同名用户按 QQ 号区分。
群角色由平台实时查询后提供给模型，查询失败标为未确认；权限仍由程序检查。
旧数据库启动时自动增加字段，保留原记录；过去未保存的昵称和引用关系不会凭空补造。

权限顺序为：机器人所有者（`BOT_OWNERS`）> 当前群的群主、群管理员 > 普通用户。
群主和群管理员可管理本群会话、记忆与积极性，不能 `/清空全部`；此操作仅限机器人所有者。
群角色在执行管理指令时实时查询，查询失败不授予管理权限。私聊不继承群管理权限。
`BOT_OWNERS` 修改后重启生效；无需配置群或用户白名单。

每次回答给模型提供本地名单、当前发言者的平台QQ号及权限级别，优先于历史记忆和身份自述。
可用 `USER_NAMES={"123456789":"你希望的称呼"}` 给账号配置名称；没有配置名字时按QQ号识别，不猜测真实姓名。
这些信息允许机器人认识所有者，但不能使模型绕过程序检查或修改权限。
本地默认人设和风格不对群内导出；群管理者可通过专用指令切换本群覆盖。


### 私聊与平台称呼

好友或与机器人同在机器人已加入的群中的成员可以直接私聊，不需要 @。每条私聊处理前通过 OneBot 查询好友与群成员资格；无法确认资格的陌生人不响应、不入库。机器人所有者身份本身不绕过此限制。

原始私聊记录按联系人隔离保存；通过公开性审核的普通信息按 QQ 号跨群聊、私聊共享，形成一致的认知。敏感、保密记录不加入共享层。内部使用负的联系人 QQ 号作为独立会话范围；已有群聊数据无需迁移。`/清空` 在私聊中只清理自己的私聊，不能通过私聊指定其他成员或“本群”；所有者的 `/清空全部` 包括群聊与私聊，仍需确认。

群聊优先使用群名片，其次 QQ 昵称，本地 `USER_NAMES` 可覆盖称呼。群成员名单最多每五分钟刷新一次，当前发言者的称呼随事件更新。名称仅用于显示，不能授予权限；机器人所有者与 QQ 群主仍是独立身份。

主动分享已启用（本地 `PROACTIVE_SHARE_ENABLED=false` 可关闭发送，保留认知审核）。模型自行选择值得分享的普通私聊完整片段和一个共同机器人已加入的群。代码拦截敏感关键词、长数字、链接等，结合最近20条本人发言进行两次独立模型审核；不确定时不共享。模型审核可能误判，不能保证绝对隐私识别。

发送前重新核验共同群；每群每小时最多一次、每人每天最多一次。发送状态持久化，发送结果不明时不自动重试。只转发不超过500字的原文，标注原说话者QQ号；不拼接或编造聊天片段。启动前的旧消息仅审核为共享认知，不补发到群。

后台每分钟最多审核两条存量消息，私聊回复后立即审核当前片段。`/记忆` 会合并同一QQ号经审核的跨会话认知；原始最近对话仍按会话隔离。清空源会话会同时使其共享认知失效，不会撤回已经发到QQ群里的消息。保密要求会撤销该会话先前的共享认知；已发消息无法自动收回。

转发使用 NapCat 合并转发消息，保留片段原说话者的 QQ 号和群昵称。正常的自然语言分享/测试请求不再因缺少“趣味性”被拒绝，仍需通过隐私审核。运行日志用 `share_review`、`share_skip`、`share_sent` 记录结果，不记录私聊正文。


### 主动参与群聊

机器人已加入的群的全部消息都会归档；最近15分钟内的30条消息进入多人话题上下文（每条最多400字）。默认积极性50，短时间消息合并，结合本地人设、群兴趣、是否在追问机器人等因素决定接话。模型判断话题结束就停止主动参与，新话题可重新加入；10分钟无决策会清除旧话题状态。不会靠定时器无消息自言自语。

每群独立调整：

- `/积极性` 查看当前数值，普通成员可用。
- `/积极性 0` 关闭主动参与，@仍回应。
- `/积极性 30` 较克制，`/积极性 50` 默认，`/积极性 80` 更积极。
- 修改仅限机器人所有者、当前群的群主和群管理员。

`group_chat.json` 是被 Git 忽略的本地配置，请勿上传；首次启动会自动生成，也可复制 `group_chat.example.json` 后修改。设置持久保存在本地 `group_chat.json`，每次决策重新读取；`default_activity` 是未单独配置群的默认值，`groups` 以群号为键。例如：

```json
{
  "default_activity": 50,
  "groups": {
    "987654321": {"activity": 50, "interests": ["编程", "天文"]}
  }
}
```

`interests` 只在本地编辑，不通过聊天查看或修改；默认空列表，仍参考本地人设中的兴趣。数值影响参与门槛及检查间隔，并不表示固定回复概率或每条必回。普通消息约合并2秒，在持续活跃群中按积极性限速（100时约10秒、50时35秒、低积极性时更长）；@不受这个主动参与间隔限制。引用回复由模型决定，仅引用当前触发消息。新消息到来可取消尚未发出的过时主动回复，接口出错时不在群内刷错误提示。

程序提示会按本地人设与风格重新表达，并校验含义及命令、数字、确认码。帮助列表和记忆条目原样保留，改写引导语。模型故障、繁忙或8秒内未完成时回退到原提示，操作结果不会因此丢失；同一风格下相同提示缓存5分钟。


### 群聊范围

机器人加入群后即可接收消息和参与聊天，无需白名单。旧 `ALLOWED_GROUPS`、`AUTHORIZED_USERS` 配置不再生效，`/白名单` 指令已移除。


### 模型主动查历史与跨群发言

模型可以通过 `read_history` 自行列出可访问会话，按时间、发送者、关键词查询消息，
分页继续查找、读取前后文，或查询当前用户认知。没有配置联网搜索也能使用本地历史工具。
“昨天”按 UTC+8 的自然日理解；空关键词可直接查询某段时间机器人自己的发言。
每次回复或群聊参与判断最多调用工具6次，可用 `HISTORY_MAX_CALLS` 调整（1～12）；
联网搜索还受原有独立上限约束。查到历史后，群聊参与判断仍可选择沉默。

私聊可以查当前私聊和经平台核验的共同群；群聊只查本群原始历史。
其他人的私聊不可查询。工具检索覆盖本地现存消息，不补抓启用前或已删除的记录；
最早、最晚记录时间不代表该时间段记录完整。查询结果分页、单条过长会标记截断。

可在私聊中说“去某某群露露脸”或“挑一个共同群打个招呼”。模型先查群名和ID，
选定目标并拟一句话，通过 `send_group_message` 实际发送。目标仍有歧义时询问用户。
发送前独立核验当前请求是否明确要求发言，并重新确认共同群资格。
此功能用于机器人自行发言，不转述私聊原文；私聊分享仍走既有审核流程。
每个请求最多尝试发送一个群、500字；发送尝试持久记录，结果不明时不自动重试。
发送成功才回报成功，且机器人消息继续归档供后续查询。

代码更新后重启机器人生效，无需手工迁移数据库；新增表和索引在启动时自动建立。


### 图片理解和本地表情包

表情包目录默认为项目根目录的 `emotes/`，使用说明见 [emotes/README.md](emotes/README.md)。
直接放入 PNG、JPG、JPEG、GIF、WebP 文件，文件名写清情绪或用途，如 `鲸鱼娘_无语.png`。
模型按文件名检索并选择，每次最多一张，可搭配文字或只发表情；群聊积极性和冷却仍生效。
文件增删下次查询即生效，无需重启；默认单张不超过5 MB，仅读取此目录直属文件。
通过Base64图片消息发送，NapCat不必与机器人共享文件路径。已导入19张鲸鱼娘精选表情并建立内容记忆，来源见 [emotes/SOURCES.md](emotes/SOURCES.md)。

图片直接放入当前聊天模型请求，使用现有 `LLM_PROVIDER`、模型名和密钥，不再调用独立视觉模型生成摘要。
本项目当前使用的 `deepseek-flash` 支持原生图片输入。配置其他模型时也须选择支持图片的模型。
不需要 `VISION_BASE_URL`、`VISION_MODEL` 或 `VISION_API_KEY`，旧的这些字段已不再使用。

```dotenv
VISION_MAX_IMAGES=3
EMOTES_DIR=emotes
EMOTES_MAX_BYTES=5242880
```

私聊、群聊的参与判断和回复都可直接结合图片与文字理解，支持引用消息中的图片；
群聊支持同一人先发图、90秒内紧接一句文字的情况。默认每次最多附3张（当前图优先）。
不会对每条未参与处理的群消息持续识图。取图失败或超出上限时明确标记未附图片，不凭空描述。
QQ图片链接会发送至当前聊天模型服务，需要模型服务能访问链接；原图与临时链接不写入聊天档案。
历史保存原始图片占位和机器人实际回复，不再生成或持久化单独的识别摘要。
跨轮追问可利用已有文字回答；需要重新查看原图细节时，请引用或重发图片。

选择表情包时，`list_emotes` 每页返回3张候选并附上实际图片（Base64），
聊天模型根据画面、图中文字、情绪与语境选择，文件名只用于初步检索。
首次看图后必须调用 `remember_emotes` 保存全部新候选的内容描述，再选择发送。
内容记忆持久保存在表情目录的 `.memory.sqlite3`，后续检索同时匹配文件名和描述。
已有记忆时只传描述，不重复附原图；首次学习完成后也会从本轮上下文移除候选原图。
记忆按图片内容SHA-256关联：重启、改名和同图副本可复用，文件内容变化则重新识别。
删除图片后该文件不再出现在候选中；不清空图片时旧内容记忆仍可供同图副本复用。
文件名不明确可先空关键词浏览，再分页；只有已查看原图并保存记忆、或已经有内容记忆的候选可以被选择。
每次回复的候选预览总量限制为14 MiB编码数据，不保证一次浏览完全部图库。
尚无记忆的本地表情图片会发送给当前模型服务用于理解，并计入图片输入费用；发往QQ时仍保持原文件。
GIF支持原样发送，模型是否理解完整动画取决于其视觉能力。

更新代码后重启机器人生效，原有表情包增删仍无需重启。
图片格式参考：[DeepSeek 官方视觉文档](https://api-docs.deepseek.com/guides/vision/)。


### 自主收藏表情包

`EMOTES_AUTO_COLLECT=true` 默认开启。模型可按语境决定收藏群友在本轮发送或引用的通用表情图，
也可用 `search_emote_images` 联网寻找新表情；联网图片搜索复用 Tavily 的 `SEARCH_API_KEY`，
未配置时只开放群图收藏，不提供虚假的联网结果。搜索次数与普通联网搜索共用上限。
此功能在收到聊天消息时按需运行，不额外定时联网。群聊可以收藏后保持沉默；积极性0时仍只处理显式触发。

流程为查看候选 → 下载并查看实际图片 → 决定收藏。新图片使用当前聊天模型核验是否适合作为
通用表情并生成内容记忆；私人照片、隐私截图、敏感资料和不确定内容不入库，私聊图片不自动纳入候选。
模型判断可能有误，图库仍可由维护者检查和删除。收藏不代表向任何群发送，发送仍需原有选择工具。

下载只允许公网HTTP(S)，检查每次重定向并锁定已验证的IP，限制超时与文件大小，不携带模型密钥或Cookie。
每条消息的参与判断与回复共用最多2次图片检查、2次收藏额度；默认滚动24小时最多新增20张，
通过 `EMOTES_DAILY_IMPORT_LIMIT` 调整；图库上限1000个有效文件。
相同图片按SHA-256去重，复用内容记忆。新图以 `收藏_<SHA256>.png/jpg/gif/webp` 存入 `emotes/`，
画面内容描述作为可检索记忆保存，不依赖长文件名。来源类型与去除查询参数的网络地址保存在
`.memory.sqlite3` 的 `emote_imports` 表；群图片只记录群范围，不保存临时下载链接。
